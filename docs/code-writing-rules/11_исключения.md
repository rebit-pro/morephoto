# Exceptions - работа с исключениями

При проектировании методов и функций используем подход "раннего возврата" (Early Exit).

## Теория раннего возврата

"Ранний возврат" — это подход к проектированию кода, который особенно полезен при обработке исключений и ошибок. Основная идея заключается в том, чтобы как можно раньше обнаруживать и обрабатывать ошибки, сокращая количество вложенных условий и улучшая читаемость кода.

## Основные принципы раннего возврата

1. **Проверяйте ошибки в первую очередь** — валидация входных данных происходит в начале метода.
2. **Выходите/выбрасывайте исключение из метода/функции при обнаружении проблемы** — не дожидайтесь конца метода.
3. **Минимизируйте вложенность кода** — каждая проверка выходит отдельно.
4. **Делайте "happy path" (удачный путь без исключений) основным и заметным** — основная логика видна.

## Пример без раннего возврата (плохая практика)

```php
public function getUserById(int $id): User
{
    if (0 < $id) {
        $user = UserTable::getById($id)->fetchObject();
        if ($user instanceof User) {
            if ($user->isActive()) {
                return $user;
            } else {
                throw new UserNotActiveException('User is not active');
            }
        } else {
            throw new UserNotFoundException('User not found');
        }
    } else {
        throw new InvalidArgumentException('ID must be positive');
    }
}
```

## Пример с ранним возвратом (хорошая практика)

```php
public function getUserById(int $id): User
{
    if (0 >= $id) {
        throw new InvalidArgumentException('ID must be positive');
    }

    $user = UserTable::getById($id)->fetchObject();
    if (!$user instanceof User) {
        throw new UserNotFoundException('User not found');
    }

    if (!$user->isActive()) {
        throw new UserNotActiveException('User is not active');
    }

    return $user;
}
```

## Преимущества быстрого выхода

1. **Улучшенная читаемость** — основной путь выполнения кода не загроможден вложенными условиями.
2. **Упрощенный поток выполнения** — ошибки обрабатываются сразу при их обнаружении.
3. **Снижение сложности** — уменьшается цикломатическая сложность функции.
4. **Лучшая поддерживаемость** — проще добавлять новые проверки.
5. **Явное выделение "счастливого пути"** — основной сценарий визуально выделен в конце метода.

## Лучшие практики

1. **Используйте конкретные типы исключений** для разных ошибок — не выбрасывайте просто Exception.
2. **Добавляйте информативные сообщения** в исключения — помогут при отладке.
3. **Логируйте исключения** на соответствующем уровне, а не в методах — централизованная обработка.
4. **Не злоупотребляйте** — иногда простая условная логика лучше исключений.
5. **Сохраняйте контекст** — включайте в исключение полезную отладочную информацию.

### Пример с информативным исключением

```php
try {
    $user = $this->getUserById($id);
} catch (UserNotFoundException $e) {
    $this->logger->warning('User not found', ['id' => $id, 'exception' => $e]);
    // Обработка ошибки
} catch (UserNotActiveException $e) {
    $this->logger->info('User is inactive', ['id' => $id]);
    // Другая обработка
}
```
