# Именование переменных и методов

## 1. Понятные, лаконичные, конкретные наименования переменных, направлены на повышение читаемости кода. Не использовать транслит с русского.

### 1.1. Имя переменной должно отражать ее назначение

Не использовать тип хранимых данных в названии (кроме случаев разных форматов одних данных). Польская нотация запрещена.

```php
// Некорректно
$arProducts;
$tovari;

// Корректно (в случае наличия переменной $products при перекодировке из JSON)
$productsJson;

// Корректно
$products;
```
### 1.2. Конкретные названия вместо абстрактных

```php
// Например: мы в цикле бежим по интервалам курьерской доставки

// Некорректно
$element;
$item;

// Корректно
$interval;
$deliveryInterval;
```
### 1.3. Отказ от кратких наименований

```php
// Некорректно
$itm;
$elem;
$elm;
$intrvl;

// Корректно
$element;  // в случае элемента инфоблока
$interval;

// Допустимо
for $i = 0
catch(\Exception $e) 
```
### 1.4. Извлечение переменных при работе с массивами/объектами

```php
// Некорректно
echo "Имя пользователя: " . $data['user']['profile']['name'] . PHP_EOL;
echo "Длина имени: " . strlen($data['user']['profile']['name']) . PHP_EOL;

// Корректно
$userName = $data['user']['profile']['name'];
echo "Имя пользователя: " . $userName . PHP_EOL;
echo "Длина имени: " . strlen($userName) . PHP_EOL;
```
### 1.5. Интерполяция вместо конкатенации, кроме hot-code. Для интерполяции допустимы двойные кавычки.

```php
// Некорректно
echo "Пользователь " . $name . " - " . $age . " лет, проживает в " . $city . " и работает как " . $profession . ".";

// Корректно
echo "Пользователь {$name} - {$age} лет, проживает в {$city} и работает как {$profession}.";

// Также корректно
$output = sprintf(
    "Пользователь %s - %d лет, проживает в %s и работает как %s.",
    $name,
    $age,
    $city,
    $profession,
);
echo $output;
```
## 2. Имена методов и функций должны максимально точно отражать то, что они делают и что возвращают

- Как и для переменных методы не должны иметь сокращений в названии. За исключением общепринятых (Id, Uuid, Json и т.п.)
- Не добавляйте лишние слова, если они не добавляют значимой информации.
- Если метод возвращает значение, его имя должно указывать, что именно он возвращает.
- Не используем транслит

```php
// Плохо: Неясно, что возвращает метод, т.к. подразумевается объект из названия
function getWarningIblock(): int

// Хорошо: Ясно, что метод возвращает ID информационного блока
function getWarningIblockId(): int

// Плохо: Неясно, что возвращает функция, если мы встретим в коде checkUser($user)
function checkUser(User $user): bool
{
    return 'active' === $user->getStatus();
}

// Хорошо: Ясно, что функция проверяет активность пользователя и возвращает bool
function isUserActive(User $user): bool
{
    return 'active' === $user->getStatus();
}
```

## Префиксы и их назначение

### 0. **get**

  - **Описание**:Самый распространенный префикс, показывает, что метод что-либо возвращает.
  - **Примеры**:
    - `getUserList` — возвращает список пользователей.
    - `getUserPhone` — возвращает телефон пользователя.
  - **Рекомендации**:
    - Не используется в специфических методах, где более логично использовать `generate`, `calculate` и т.п.
### 1. **is**

  - **Описание**:Используется для обозначения булевых переменных или методов, которые возвращают логическое значение (`true`/`false`), связанное с состоянием объекта.
  - **Примеры**:
    - `isActive` — указывает, активен ли объект.
    - `isVisible` — указывает, видим ли элемент на экране.
    - `isValid` — проверяет, является ли значение корректным.
  - **Рекомендации**:
    - Используйте только для булевых значений.
    - Название должно быть утвердительным (например, `isActive`, а не `isNotActive`).
### 2. **has**

  - **Описание**:Указывает на наличие или отсутствие определенного свойства, ресурса или состояния.
  - **Примеры**:
    - `hasPermission` — проверяет, есть ли у пользователя определенные права.
    - `hasChildren` — указывает, содержит ли объект дочерние элементы.
    - `hasError` — проверяет, произошла ли ошибка.
  - **Рекомендации**:
    - Префикс подходит для случаев, когда нужно ответить на вопрос "есть ли что-то?".
### 3. **can**

  - **Описание**:Обозначает возможность выполнения какого-либо действия или операции.
  - **Примеры**:
    - `canEdit` — проверяет, может ли пользователь редактировать объект.
    - `canDelete` — проверяет, доступно ли удаление.
    - `canProceed` — указывает, можно ли продолжить выполнение процесса.
  - **Рекомендации**:
    - Используйте для методов или переменных, связанных с проверкой прав или условий.
### 4. **should**

  - **Описание**:Указывает на рекомендацию или необходимость выполнения действия.
  - **Примеры**:
    - `shouldUpdate` — указывает, нужно ли обновлять данные.
    - `shouldRetry` — проверяет, следует ли повторить попытку.
  - **Рекомендации**:
    - Префикс подходит для ситуаций, где решение принимается на основе логики или условий.
### 5. **will**

  - **Описание**:Обозначает намерение выполнить действие в будущем.
  - **Примеры**:
    - `willExecute` — указывает, будет ли выполнено действие.
    - `willChange` — проверяет, изменится ли состояние.
  - **Рекомендации**:
    - Используйте для методов или переменных, связанных с планированием или предсказанием.
### 6. **was**

  - **Описание**:Используется для обозначения прошлого состояния объекта.
  - **Примеры**:
    - `wasSuccessful` — указывает, был ли процесс успешным.
    - `wasCancelled` — проверяет, был ли процесс отменен.
  - **Рекомендации**:
    - Применяйте для переменных, которые хранят исторические данные.
### 7. **calculate**

  - **Описание**:Используется для обозначения того, что метод что-то вычисляет
  - **Примеры**:
    - calculateDiscountedPrice — указывает, что вычисляется цена со скидкой.
    - calculateDeliveryPrice — указывает, что вычисляется цена доставки.
  - **Рекомендации**:
    - Не верно тут использовать префикс `get`
### 8. generate

  - **Описание**:Используется для обозначения методов или функций, которые генерируют новые данные, объекты или значения. Это может быть полезно для создания уникальных идентификаторов, случайных строк, массивов данных или других сущностей
  - **Примеры**:
    - generateUserUuid — указывает, что генерируется новый Uuid для пользователя.
    - generateRandomString — генерация случайной строки.
  - **Рекомендации**:
    - Не верно тут использовать префикс `get`
### 9. validate

  - **Описание**:Используется для обозначения того, что метод что-то проверяет и выбрасывает исключение при неудаче.
  - **Примеры**:
    - validateAge(int $age): void — указывает, что проверяется возраст
  - **Рекомендации**:
    - Метод обязательно `void`
    - В phpdoc указывается исключение, которое он выбрасывает.
### 10. check

  - **Описание**:Используется для обозначения того, что метод что-то проверяет и возвращает bool.
  - **Примеры**:
    - checkIsActive(User $user): bool — проверяет активен ли пользователь
  - **Рекомендации**:
    - Метод обязательно `bool`
    - Если это возможно, то лучше использовать `validate`из-за "раннего возврата"
## Общие рекомендации

  1. **Читаемость**: Названия должны быть понятными и однозначными. Избегайте двусмысленных формулировок.
  2. **Контекст**: Убедитесь, что префикс соответствует контексту использования переменной.
  3. **Единообразие**: Следуйте единым правилам именования в рамках проекта.
  4. **Булевы значения**: Все префиксы (`is`, `has`, `can`, и т.д.) должны возвращать или представлять булевы значения.
