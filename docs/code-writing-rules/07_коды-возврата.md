# Коды возврата из контроллеров

## Основные HTTP-коды возврата в RESTful API

При разработке RESTful API важно использовать правильные HTTP-коды возврата, чтобы клиент мог однозначно интерпретировать результат выполнения запроса.

**В проекте** HTTP-коды возвращаются через **выброс исключений, наследующих `HttpException`**. Контроллер сам не возвращает ошибочные коды — исключения перехватываются в `finalizeResponse()` и преобразуются в JSON ответ.

Важно не путать два уровня правил:
- на уровне HTTP-слоя ошибки сериализуются через `HttpException`;
- на уровне `Application` по умолчанию лучше держать предметные исключения, не завязанные на транспорт.

## Базовый подход и допустимое исключение

По умолчанию правило такое:
- `Application` не знает про HTTP;
- `Presentation` транслирует предметную ошибку в `HttpException`;
- такой подход предпочтителен, если один и тот же `UseCase` может вызываться не только из API.

Но в проекте допустимо **осознанное исключение для чисто API-модулей**:
- модуль не используется из CLI, компонентов и других non-HTTP entrypoint;
- `UseCase` не предполагается переиспользовать вне API;
- команда явно договорилась снижать оверкод и не плодить дублирующие exception-слои.

В таком модуле допускается, чтобы исключение `Application` сразу наследовало `HttpException`.
Главное правило здесь не в том, чтобы всегда запрещать такой подход, а в том, чтобы **выбрать один стиль на модуль и зафиксировать его в документации**.
Как пример выступает модуль rebit.bybit.

### 1xx — Информационные

| Код | Название | Описание |
|---|---|---|
| 100 | Continue | Сервер готов принять тело запроса |
| 101 | Switching Protocols | Переключение протокола |

### 2xx — Успешные запросы

| Код | Название | Описание | Когда использовать |
|---|---|---|---|
| 200 | OK | Успешно | Получение или обновление данных |
| 201 | Created | Создано | Успешное создание нового ресурса (POST) |
| 202 | Accepted | Принято | Запрос принят на обработку (асинхронные операции) |
| 204 | No Content | Нет содержимого | Успешное удаление или операция без ответа |

### 3xx — Перенаправления

| Код | Название | Описание |
|---|---|---|
| 301 | Moved Permanently | Ресурс перемещен навсегда |
| 302 | Found | Временное перенаправление |
| 304 | Not Modified | Ресурс не был изменен |

### 4xx — Ошибки клиента

| Код | Название | Описание | Когда использовать |
|---|---|---|---|
| 400 | Bad Request | Плохой запрос | Ошибка валидации входных данных |
| 401 | Unauthorized | Не авторизован | Отсутствуют или некорректные учетные данные |
| 403 | Forbidden | Доступ запрещен | Пользователь не имеет прав |
| 404 | Not Found | Не найдено | Ресурс не существует |
| 409 | Conflict | Конфликт | Конфликт при выполнении операции |
| 422 | Unprocessable Entity | Невозможно обработать | Ошибка валидации данных |
| 429 | Too Many Requests | Слишком много запросов | Rate limiting |

### 5xx — Ошибки сервера

| Код | Название | Описание |
|---|---|---|
| 500 | Internal Server Error | Внутренняя ошибка сервера |
| 502 | Bad Gateway | Ошибка шлюза |
| 503 | Service Unavailable | Сервис недоступен |

## Подход в проекте: HttpException наследники

В проекте HTTP-коды достигаются через **выброс исключений**, наследующих `HttpException`. Контроллер перехватывает их в `finalizeResponse()` и преобразует в JSON ответ с соответствующим кодом.

Ниже показан упрощённый API-ориентированный вариант, где исключение прикладного слоя уже умеет сериализоваться в HTTP-ответ. Используйте его только там, где это согласовано как исключение для чисто API-модуля.

### Структура HttpException

Каждое исключение для API наследует `HttpException` и определяет:
- `HTTP_DEFAULT_EXCEPTION_CODE` — HTTP-код ответа
- `DEFAULT_ERROR_MESSAGE` — сообщение об ошибке

```php
<?php

declare(strict_types=1);

namespace Rebit\Wallet\Application\Product\Exception;

use Rebit\Share\Shared\Exception\HttpException;

final class ProductNotFoundException extends HttpException
{
    public const int HTTP_DEFAULT_EXCEPTION_CODE = 404;
    public const string DEFAULT_ERROR_MESSAGE = 'Товар не найден';
}
```

### Пример использования в контроллере

```php
<?php

declare(strict_types=1);

namespace Rebit\Wallet\Controller\Product;

use Bitrix\Main\HttpResponse;
use Rebit\Wallet\Application\Product\Exception\ProductNotFoundException;
use Rebit\Wallet\Application\Product\UseCase\ProductListQueryUseCase;
use Rebit\Wallet\Application\Product\UseCase\CreateProductUseCase;
use Rebit\Wallet\Domain\Product\Entity\Product;
use Rebit\Wallet\Application\Product\Dto\ProductCreateRequestDto;
use Rebit\Share\Infrastructure\Bitrix\ControllerJson;
use Rebit\Share\Infrastructure\Controller\BaseJsonController;

final class ProductController extends BaseJsonController
{
    public function __construct(
        private readonly ProductListQueryUseCase $listUseCase,
        private readonly CreateProductUseCase $createUseCase,
        private readonly DeleteProductUseCase $deleteUseCase,
    ) {
        parent::__construct();
    }

    // 200 OK — получение списка
    public function listAction(): ControllerJson
    {
        return $this->json($this->listUseCase->execute());
    }

    // 404 Not Found — Entity не найдена (автоматически через RequestToEntityMapper)
    // Если ID не существует, выбрасывается EntityNotFoundException (404)
    public function getAction(Product $product): ControllerJson
    {
        return $this->json($product);
    }

    // 201 Created — создание ресурса
    public function createAction(ProductCreateRequestDto $dto): HttpResponse
    {
        $this->createUseCase->execute(
            name: $dto->name,
            price: $dto->price,
        );

        return $this->created();
    }

    // 204 No Content — удаление без ответа
    public function deleteAction(Product $product): HttpResponse
    {
        $this->deleteUseCase->execute($product->getId());

        return $this->noContent();
    }
}
```

## Распространённые исключения HTTP в проекте

| Код | Исключение | Путь |
|---|---|---|
| 400 | `ValidationHttpException` | `Rebit\Share\Infrastructure\Exception` |
| 404 | `EntityNotFoundException` | `Rebit\Share\Infrastructure\Exception` |
| 401 | `HttpException` (или свой класс с кодом 401) | Зависит от модуля |
| 500 | `HttpException` (по умолчанию) | `Rebit\Share\Shared\Exception` |

### Методы BaseJsonController

```php
// 200 OK с данными (ResultDtoInterface или массив)
$this->json($data);

// 201 Created
$this->created();

// 204 No Content (удаление без тела ответа)
$this->noContent();
```

**Примечание:** Других методов для возврата ошибочных кодов нет — используйте исключения.
