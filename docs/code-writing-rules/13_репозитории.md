# Репозитории

В проекте используются **два типа репозиториев** с разными правилами размещения и оформления.

---

## 1. Доменные репозитории (Bitrix ORM)

Работают напрямую с Bitrix ORM (`*Table`, `Entity`, `Collection`). Живут в доменном слое, **не требуют интерфейса** — ORM является частью доменной модели в нашем проекте.

**Расположение:** `lib/Domain/<Aggregate>/Repository/<Name>Repository.php`

### Что возвращает доменный репозиторий

- `Entity` — доменная сущность (наследник `EO_*`)
- `Collection` — коллекция сущностей (наследник `EO_*_Collection`)
- `Result` — результат операции Bitrix ORM
- Скалярные типы и их массивы
- **Никогда не возвращает** «сырые» ассоциативные массивы или DTO

### Правила

1. **`final class`**, без интерфейса — привязан к конкретной ORM-таблице.
2. **Один репозиторий на агрегат** — все операции с одной сущностью в одном месте.
3. **Не содержит бизнес-логики** — только операции с хранилищем.
4. **Кеширование** через `setCacheTtl()` ORM следует избегать!
5. **Предметные исключения** — заворачивает ошибки в `*NotFoundException` / `*RepositoryException`.
6. Конвенция именования: `get*` — бросает исключение, если не найдено; `find*` — возвращает `null`.

### Пример: SalonRepository

```php
<?php

declare(strict_types=1);

namespace Rebit\Identity\Domain\Salon\Repository;

use Bitrix\Main\ArgumentException;
use Bitrix\Main\ObjectPropertyException;
use Bitrix\Main\SystemException;
use Rebit\Identity\Domain\Salon\Entity\Salon;
use Rebit\Identity\Domain\Salon\Entity\SalonCollection;
use Rebit\Identity\Domain\Salon\Entity\Table\SalonTable;

final class SalonRepository
{
    /**
     * @throws ArgumentException
     * @throws ObjectPropertyException
     * @throws SystemException
     */
    public function findById(int $id): ?Salon
    {
        return SalonTable::query()
            ->setSelect($this->getSelectFields())
            ->where('ID', $id)
            ->setLimit(1)
            ->exec()
            ->fetchObject()
        ;
    }

    /**
     * @param int[] $ids
     *
     * @throws ArgumentException
     * @throws ObjectPropertyException
     * @throws SystemException
     */
    public function getByIds(array $ids): SalonCollection
    {
        if ([] === $ids) {
            return new SalonCollection();
        }

        return SalonTable::query()
            ->setSelect($this->getSelectFields())
            ->whereIn('ID', $ids)
            ->exec()
            ->fetchCollection()
        ;
    }

    private function getSelectFields(): array
    {
        return [
            'ID',
            'NAME',
            'XML_ID',
            'ID1C_' => 'ID_1C.VALUE',
            'ADDRESS_' => 'ADDRESS.VALUE',
        ];
    }
}
```

## 2. Порты внешних хранилищ (DDD-репозитории)

Для внешних хранилищ (Elasticsearch, внешние API, сторонние сервисы) используется паттерн **Port / Adapter**:

- **Port** (интерфейс) — в Application-слое, описывает контракт доступа к данным.
- **Adapter** (реализация) — в Infrastructure-слое, реализует порт для конкретного хранилища.

Это классические DDD-репозитории: Application-слой зависит только от абстракции (интерфейса), а конкретная реализация подставляется через DI.

### Расположение

| Элемент | Путь |
|---------|------|
| Port (интерфейс) | `lib/Application/<Domain>/Port/Outgoing/<Name>Interface.php` |
| DTO входа/выхода | `lib/Application/<Domain>/Port/Dto/<Category>/<Name>Dto.php` |
| Предметное исключение | `lib/Application/<Domain>/Exception/<Name>Exception.php` |
| Infrastructure (реализация) | `lib/Infrastructure/<Domain>/.../<Name>.php` |
| Legacy Adapter | `lib/Infrastructure/LegacyAdapter/<Domain>/<Name>.php` |

### Правила

1. **Интерфейс** содержит предметные имена методов (`query`, `listItems`, `create`), не `execute`.
2. **Реализация** — `final readonly class`, зависимости через конструктор.
3. **Ошибки инфраструктуры** оборачиваются в предметные исключения Application-слоя.
4. **Принимает и возвращает Application DTO** — инфраструктурные детали не просачиваются наружу.
5. **Привязка** порта к реализации — в `di/`-конфигах модуля.

### Пример: Port (интерфейс)

```php
<?php

declare(strict_types=1);

namespace Rebit\Wallet\Application\Facet\Port\Outgoing;

use Rebit\Wallet\Application\Facet\Port\Dto\Query\FacetProductListInputDto;
use Rebit\Wallet\Application\Facet\Port\Dto\Query\FacetProductListOutDto;
use Rebit\Wallet\Application\Facet\Exception\FacetQueryException;

interface FacetProductListQueryInterface
{
    /**
     * @param int[] $propertyIds ID свойств, которые отображаются в умном фильтре раздела
     *
     * @throws FacetQueryException
     */
    public function query(FacetProductListInputDto $filter, array $propertyIds): FacetProductListOutDto;
}
```

### Пример: Infrastructure (реализация для Elasticsearch)

```php
<?php

declare(strict_types=1);

namespace Rebit\Wallet\Infrastructure\Facet\Provider\Elastic\Contract;

use Elasticsearch\Client;
use Rebit\Wallet\Application\Facet\Port\Dto\Query\FacetProductListInputDto;
use Rebit\Wallet\Application\Facet\Port\Dto\Query\FacetProductListOutDto;
use Rebit\Wallet\Application\Facet\Exception\FacetQueryException;
use Rebit\Wallet\Application\Facet\Port\Outgoing\FacetProductListQueryInterface;
use Rebit\Wallet\Infrastructure\Facet\Provider\Elastic\ElasticFacetQueryBuilder;

final readonly class ElasticFacetProductListQuery implements FacetProductListQueryInterface
{
    public function __construct(
        private Client $elasticsearch,
        private ElasticFacetQueryBuilder $elasticFacetQueryBuilder,
    ) {}

    /**
     * @throws FacetQueryException
     */
    public function query(FacetProductListInputDto $filter, array $propertyIds): FacetProductListOutDto
    {
        try {
            $elasticQuery = $this->elasticFacetQueryBuilder->buildProductListQuery(
                $this->mapToInfrastructureDto($filter),
                $propertyIds,
            );
            $response = $this->elasticsearch->search($elasticQuery);
        } catch (\Exception $e) {
            throw new FacetQueryException($e->getMessage(), $e->getCode(), $e);
        }

        $aggregations = $response['aggregations'] ?? [];

        return new FacetProductListOutDto(
            productIds: $this->parseIds($aggregations['product_ids']['buckets'] ?? []),
            sectionIds: $this->parseIds($aggregations['section_ids']['buckets'] ?? []),
        );
    }
}
```

### Пример: DI-конфигурация (привязка порта к реализации)

Ключ DI-регистрации может быть как конкретным классом, так и интерфейсом.
Способ регистрации зависит от того, является ли ключ интерфейсом и нужна ли ручная сборка.

**Concrete-class key** — стандартная запись через `className + constructorParams`:

```php
// di/Facet.php
return [
    FacetProductListQueryUseCase::class => [
        'className' => FacetProductListQueryUseCase::class,
        'constructorParams' => static fn(): array => [
            ServiceLocator::getInstance()->get(FacetProductListQueryInterface::class),
            ServiceLocator::getInstance()->get(FacetAppService::class),
        ],
    ],
];
```

**Interface key** — если реализация собирается вручную, используется `constructor` (не `className + constructorParams`, Bitrix игнорирует `constructorParams` для interface-key):

```php
FacetProductListQueryInterface::class => [
    'constructor' => static fn(): FacetProductListQueryInterface => new ElasticFacetProductListQuery(
        ServiceLocator::getInstance()->get(ElasticClientFactory::class)->create(),
        ServiceLocator::getInstance()->get(ElasticFacetQueryBuilder::class),
    ),
],
```

**Interface key без ручной сборки** — допустим `className` как alias:

```php
FooGatewayInterface::class => [
    'className' => ElasticFooGateway::class,
],
```

Подробнее — [архитектурное руководство: структура модуля и DI](../architecture-guide/03_структура-модуля-и-di.md).

**Эталоны:**
- Port: `api/public/local/modules/rebit.wallet/lib/Application/Facet/Port/Outgoing/FacetProductListQueryInterface.php`
- Infrastructure: `api/public/local/modules/rebit.wallet/lib/Infrastructure/Facet/Provider/Elastic/Contract/ElasticFacetProductListQuery.php`
- LegacyAdapter: `api/public/local/modules/rebit.wallet/lib/Infrastructure/LegacyAdapter/Promotion/PromotionListAdapter.php`

## Когда что использовать

| Хранилище | Тип | Слой |
|-----------|-----|------|
| Bitrix ORM (IBlock, HL Block, User table) | Доменный репозиторий | `Domain/<Aggregate>/Repository/` |
| Elasticsearch, Redis, внешний API | Port + Infrastructure Adapter | Port в `Application/`, Adapter в `Infrastructure/` |
| Legacy Bitrix-код (старый API) | Port + LegacyAdapter | Port в `Application/`, Adapter в `Infrastructure/LegacyAdapter/` |
