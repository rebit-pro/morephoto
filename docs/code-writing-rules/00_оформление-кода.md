# Основные правила оформления кода

## 1. Не использовать неожиданные числовые идентификаторы ("магические числа")

1. Каждый идентификатор должен быть получен через константы, env, Enum, конфиги, либо запросом к БД по символьному или внешнему коду.
2. В коде не должно быть числовых идентификаторов неизвестного происхождения.

## 2. Сравнения всегда строгие + yoda-style, используем явное приведение типов вместо `intval()`, `strval()`, `empty()` и пр.

Yoda-style дает защиту от ошибок при сравнениях, а также акцентирует взгляд на значении, а не на переменной, улучшая читаемость. Таким образом сравнения и присваивания сильно отличаются визуально.

Yoda-style — это стиль написания условий, при котором константа или литерал ставится слева от оператора сравнения, а переменная — справа. Название происходит от персонажа Йоды из "Звездных войн", который говорит в непривычном порядке слов.

### 2.1. Для скалярных переменных

```php
// Правильно (yoda-style)
if (null === $value) {
    // ...
}

if (0 === (int)$count) {
    // ...
}

// Неправильно
if ($value === null) {
    // ...
}
```

### 2.2. Для объектов

```php
// Правильно
if (null === $object) {
    // ...
}

// Неправильно (может быть ошибка присваивания)
if ($object === null) {
    // ...
}
```

### 2.3. Проверка пустой строки

```php
// Правильно
if ('' === $string) {
    // ...
}

// Неправильно
if (empty($string)) {
    // ...
}
```

## 3. Используем именованные параметры. Перенос параметров на новую строку для конструкторов и вызовов методов с 3+ переменными

```php
// Правильно
$object = new SomeClass(
    paramOne: 'value',
    paramTwo: 'value',
    paramThree: 'value',
);

// Неправильно
$object = new SomeClass('value', 'value', 'value');
```

## 4. Завершающие запятые

Всегда используем завершающую запятую при переносе параметров и элементов массивов.

```php
// Правильно
$array = [
    'key1' => 'value1',
    'key2' => 'value2',
];

$result = methodCall(
    $param1,
    $param2,
);

// Неправильно
$array = [
    'key1' => 'value1',
    'key2' => 'value2'
];
```

## 5. Используем match вместо switch или if-elseif

### 5.1. Простое сравнение значений

```php
// Правильно
$result = match ($status) {
    'active' => 'Активный',
    'inactive' => 'Неактивный',
    default => 'Неизвестный статус',
};

// Неправильно
switch ($status) {
    case 'active':
        $result = 'Активный';
        break;
    // ...
}
```

### 5.2. Сравнение с условиями

```php
// Правильно
$message = match (true) {
    $age < 18 => 'Несовершеннолетний',
    $age < 65 => 'Взрослый',
    default => 'Пенсионер',
};
```

## 6. Используем одинарные кавычки

```php
// Правильно
$string = 'This is a string';

// Неправильно
$string = "This is a string";
```

## 7. Современные строковые функции PHP 8.x

Используем: `str_starts_with()`, `str_ends_with()`, `str_contains()`

```php
// Правильно
if (str_starts_with($filename, 'test_')) {
    // ...
}

// Неправильно
if (strpos($filename, 'test_') === 0) {
    // ...
}
```

## 8. Стрелочные функции

Используем где возможно для улучшения читаемости. Указываем типы.

```php
// Правильно
$result = array_map(static fn(int $item): int => $item * 2, $array);

// Сложнее без стрелочной функции и типов
$result = array_map(function($item) {
    return $item * 2;
}, $array);
```

## 9. Статические замыкания

Все стрелочные функции и замыкания должны быть объявлены как `static`, если это возможно из контекста.

```php
// Правильно
array_filter($items, static fn(SomeObject $item): bool => $item->isActive());
```

## 10. Final readonly классы

Все классы должны объявляться как `final readonly`, где это возможно. Если класс не может быть `readonly` (например, имеет изменяемое состояние), то как минимум `final`.

```php
// Правильно
final readonly class UserService { }

// Допустимо (если readonly невозможен)
final class UserService { }

// Неправильно (без наследников)
class UserService { }
```

## 11. Final методы

Все методы абстрактных классов, которые должны быть защищены от изменений в наследниках, должны быть объявлены как `final`.

```php
abstract class BaseRepository {
    final public function save(Entity $entity): void
    {
        // ...
    }
}
```

## 12. Конструктор в стиле PHP 8.x

Поля классов объявляем в конструкторе, по умолчанию с префиксом `readonly`.

```php
// Правильно
final readonly class UserService
{
    public function __construct(
        private UserRepository $repository,
        private LoggerInterface $logger,
    ) {}
}

// Неправильно (старый стиль)
class UserService
{
    private UserRepository $repository;
    private LoggerInterface $logger;

    public function __construct(UserRepository $repository, LoggerInterface $logger)
    {
        $this->repository = $repository;
        $this->logger = $logger;
    }
}
```

## 13. Не используем выравнивание массивов и аргументов по сетке

Это сильно замусоривает git при добавлении новых значений.

**Неверное форматирование**:

```php
$array = [
    'name'   => 'John',
    'email'  => 'john@example.com',
    'status' => 'active',
];
```

**Верное форматирование**:

```php
$array = [
    'name' => 'John',
    'email' => 'john@example.com',
    'status' => 'active',
];
```

## 14. return в методах и функциях всегда с отступом в одну строку

Возврат из метода всегда выделяется пустой строкой, если перед ним есть еще строки кода. Если это единственный оператор в блоке (между `{}`), то отступ не нужен.

**Верное форматирование** — единственный оператор, отступ не нужен:

```php
public function getName(): string
{
    return $this->name;
}
```

**Верное форматирование** — перед `return` есть другой код, нужна пустая строка:

```php
public function getName(): string
{
    $name = $this->processingName();

    return $name;
}
```

## 15. Перенос длинных строк

Перенос длинных строк производится со следующего оператора.

```php
$result = $repository
    ->findByConditions()
    ->filter(static fn(SomeObject $item): bool => $item->isActive())
    ->map(static fn(SomeObject $item): array => $item->toArray());
```

## 16. Чистота кода

Не оставлять закомментированные куски кода, а также `var_dump()`, `dd()`, `dump()`, кроме случаев кратковременного тестирования функционала и запланированного отката выгруженных изменений.
