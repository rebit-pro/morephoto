# Основы разработки

## SOLID (5 ключевых принципов ООП)

SOLID — это аббревиатура пяти основных принципов объектно-ориентированного программирования и дизайна, которые помогают создавать более поддерживаемый, масштабируемый и гибкий код.

### S — Single Responsibility Principle (Принцип единственной ответственности)

Каждый класс должен иметь одну и только одну причину для изменения. Класс должен отвечать за одно.

```php
// ❌ Плохо: класс отвечает и за валидацию, и за сохранение
class UserService {
    public function validateAndSave(User $user): void {
        if (empty($user->email)) {
            throw new Exception('Email is required');
        }
        // save...
    }
}

// ✅ Хорошо: разделение ответственности
final readonly class UserValidator
{
    public function validate(User $user): void
    {
        if ('' === $user->email) {
            throw new \InvalidArgumentException('Email is required');
        }
    }
}

final readonly class UserRepository
{
    public function save(User $user): void
    {
        // save...
    }
}
```

### O — Open/Closed Principle (Принцип открытости/закрытости)

Классы должны быть открыты для расширения, но закрыты для модификации.

```php
// ❌ Плохо: необходимо менять класс при добавлении нового типа платежа
class PaymentProcessor {
    public function process(Payment $payment): void {
        if ($payment->type === 'credit_card') {
            // обработка кредитной карты
        } elseif ($payment->type === 'paypal') {
            // обработка PayPal
        }
    }
}

// ✅ Хорошо: используем полиморфизм
interface PaymentMethodInterface
{
    public function process(Payment $payment): void;
}

final readonly class CreditCardPaymentMethod implements PaymentMethodInterface
{
    public function process(Payment $payment): void
    {
        // обработка кредитной карты
    }
}

final readonly class PayPalPaymentMethod implements PaymentMethodInterface
{
    public function process(Payment $payment): void
    {
        // обработка PayPal
    }
}
```

### L — Liskov Substitution Principle (Принцип подстановки Лисков)

Объекты подклассов должны корректно заменять объекты базовых классов.

```php
// ❌ Плохо: Square нарушает контракт Rectangle
class Rectangle {
    protected int $width;
    protected int $height;

    public function setWidth(int $width): void {
        $this->width = $width;
    }

    public function setHeight(int $height): void {
        $this->height = $height;
    }

    public function getArea(): int {
        return $this->width * $this->height;
    }
}

class Square extends Rectangle {
    public function setWidth(int $width): void {
        $this->width = $width;
        $this->height = $width;  // нарушает ожидание базового класса
    }
}

// ✅ Хорошо: правильная иерархия
interface Shape
{
    public function getArea(): int;
}

final readonly class Rectangle implements Shape
{
    public function __construct(
        private int $width,
        private int $height,
    ) {}

    public function getArea(): int
    {
        return $this->width * $this->height;
    }
}

final readonly class Square implements Shape
{
    public function __construct(private int $side) {}

    public function getArea(): int
    {
        return $this->side * $this->side;
    }
}
```

### I — Interface Segregation Principle (Принцип разделения интерфейса)

Много специфичных интерфейсов лучше, чем один универсальный.

```php
// ❌ Плохо: один большой интерфейс
interface Worker {
    public function work(): void;
    public function eat(): void;
}

class Robot implements Worker {
    public function work(): void {
        // работа
    }

    public function eat(): void {
        // робот не ест!
    }
}

// ✅ Хорошо: разделенные интерфейсы
interface Workable
{
    public function work(): void;
}

interface Eatable
{
    public function eat(): void;
}

final readonly class Robot implements Workable
{
    public function work(): void
    {
        // работа
    }
}

final readonly class Human implements Workable, Eatable
{
    public function work(): void
    {
        // работа
    }

    public function eat(): void
    {
        // еда
    }
}
```

### D — Dependency Inversion Principle (Принцип инверсии зависимостей)

Зависьте от абстракций, а не от конкретных реализаций.

```php
// ❌ Плохо: зависимость от конкретного класса
class UserService {
    private MySqlUserRepository $repository;

    public function __construct() {
        $this->repository = new MySqlUserRepository();
    }
}

// ✅ Хорошо: зависимость от интерфейса
interface UserRepositoryInterface
{
    public function save(User $user): void;
}

final readonly class UserService
{
    public function __construct(
        private UserRepositoryInterface $repository,
    ) {}
}
```

## DRY (Don't Repeat Yourself)

Не повторяй себя. Если одна и та же логика встречается в нескольких местах, она должна быть извлечена в отдельный метод, класс или функцию.

```php
// ❌ Плохо: дублирование кода
public function getUserName(int $id): string {
    $result = UserTable::getById($id);
    if (!$result) {
        throw new Exception('User not found');
    }
    return $result->fetchObject()->getName();
}

public function getUserEmail(int $id): string {
    $result = UserTable::getById($id);
    if (!$result) {
        throw new Exception('User not found');
    }
    return $result->fetchObject()->getEmail();
}

// ✅ Хорошо: извлечена общая логика
private function getUserById(int $id): User
{
    $result = UserTable::getById($id);
    if (null === $result) {
        throw new UserNotFoundException('User not found');
    }

    return $result->fetchObject();
}

public function getUserName(int $id): string
{
    return $this->getUserById($id)->getName();
}

public function getUserEmail(int $id): string
{
    return $this->getUserById($id)->getEmail();
}
```

## KISS (Keep It Simple, Stupid)

Код должен быть простым и понятным. Не создавайте излишние абстракции.

```php
// ❌ Плохо: чрезмерная сложность
class ComplexCalculator {
    private function recursiveCalculate(array $items, int $index = 0): int {
        if ($index >= count($items)) {
            return 0;
        }
        return $items[$index] + $this->recursiveCalculate($items, $index + 1);
    }

    public function sum(array $items): int {
        return $this->recursiveCalculate($items);
    }
}

// ✅ Хорошо: простое решение
final readonly class SimpleCalculator
{
    /** @param int[] $items */
    public function sum(array $items): int
    {
        return array_sum($items);
    }
}
```

## YAGNI (You Aren't Gonna Need It)

Не добавляйте функциональность, которая может понадобиться в будущем. Добавляйте только то, что нужно сейчас.

```php
// ❌ Плохо: код для будущего
class UserRepository {
    public function getById(int $id): User { }
    public function getByEmail(string $email): User { }
    public function getByPhone(string $phone): User { }  // может не понадобиться
    public function getByUsername(string $username): User { }
    public function getActive(): Collection { }
    public function getInactive(): Collection { }
    public function getBanned(): Collection { }
    public function archive(User $user): void { }  // может не понадобиться
}

// ✅ Хорошо: только то, что нужно сейчас
final class UserRepository
{
    public function getById(int $id): User { }
    public function save(User $user): void { }
}
```
