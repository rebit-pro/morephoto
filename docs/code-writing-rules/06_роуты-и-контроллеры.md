# Роуты в контролерах

Общие правила разработки RESTful API описаны в статье [Общие правила разработки REST API](https://habr.com/ru/articles/351890/).

## CRUD операции и список элементов

| Метод   | URI                   | Описание              |
|---------|-----------------------|-----------------------|
| GET     | `/api/products/`      | Получить список       |
| GET     | `/api/products/{id}/` | Получить один элемент |
| POST    | `/api/products/`      | Создать ресурс        |
| PUT     | `/api/products/{id}/` | Обновить полностью    |
| PATCH   | `/api/products/{id}/` | Частичное обновление  |
| DELETE  | `/api/products/{id}/` | Удалить ресурс        |

## Пример маршрутов в `routes.php`

```php
<?php

declare(strict_types=1);

use Bitrix\Main\Routing\RoutingConfigurator;
use Rebit\Wallet\Controller\ProductController;

return static function(RoutingConfigurator $routes) {
    $routes->get('/api/v1/products/', [ProductController::class, 'listAction']);
    $routes->get('/api/v1/products/{id}/', [ProductController::class, 'getAction']);
    $routes->post('/api/v1/products/', [ProductController::class, 'createAction']);
    $routes->put('/api/v1/products/{id}/', [ProductController::class, 'updateAction']);
    $routes->delete('/api/v1/products/{id}/', [ProductController::class, 'deleteAction']);
};
```

## Пример контроллера

```php
<?php

declare(strict_types=1);

namespace Rebit\Wallet\Controller\Product;

use Bitrix\Main\HttpResponse;
use Rebit\Wallet\Application\Product\UseCase\ProductListQueryUseCase;
use Rebit\Wallet\Application\Product\UseCase\ProductGetQueryUseCase;
use Rebit\Wallet\Application\Product\UseCase\CreateProductUseCase;
use Rebit\Wallet\Application\Product\UseCase\UpdateProductUseCase;
use Rebit\Wallet\Application\Product\UseCase\DeleteProductUseCase;
use Rebit\Wallet\Application\Product\Dto\ProductCreateRequestDto;
use Rebit\Wallet\Application\Product\Dto\ProductUpdateRequestDto;
use Rebit\Wallet\Domain\Product\Entity\Product;
use Rebit\Share\Infrastructure\Bitrix\ControllerJson;
use Rebit\Share\Infrastructure\Controller\BaseJsonController;

final class ProductController extends BaseJsonController
{
    public function __construct(
        private readonly ProductListQueryUseCase $listUseCase,
        private readonly ProductGetQueryUseCase $getUseCase,
        private readonly CreateProductUseCase $createUseCase,
        private readonly UpdateProductUseCase $updateUseCase,
        private readonly DeleteProductUseCase $deleteUseCase,
    ) {
        parent::__construct();
    }

    public function listAction(): ControllerJson
    {
        return $this->json($this->listUseCase->execute());
    }

    public function getAction(Product $product): ControllerJson
    {
        return $this->json($this->getUseCase->execute($product));
    }

    public function createAction(ProductCreateRequestDto $dto): HttpResponse
    {
        $this->createUseCase->execute(
            name: $dto->name,
            price: $dto->price,
        );

        return $this->created();
    }

    public function updateAction(ProductUpdateRequestDto $dto): ControllerJson
    {
        $result = $this->updateUseCase->execute(
            id: $dto->id,
            name: $dto->name,
            price: $dto->price,
        );

        return $this->json($result);
    }

    public function deleteAction(Product $product): HttpResponse
    {
        $this->deleteUseCase->execute($product->getId());

        return $this->noContent();
    }
}
```

## Автомаппинг Entity в параметрах действия

При указании типа параметра как Entity (например `Product $product`), система **автоматически загружает сущность из БД по ID** из URL.

Это работает через `RequestToEntityMapper`:
- ID берется из пути маршрута (`{id}`)
- Entity загружается через ORM: `Product::$dataClass::getById($id)->fetchObject()`
- Если сущность не найдена — выбрасывается `EntityNotFoundException`
- Если в запросе больше одного параметра — выбрасывается `RequestParameterException`

**Важно:** Только **один параметр Entity** на одно действие. Для дополнительных данных используйте `RequestDto`.

### Роут

```php
$routes->get('/api/v1/products/{id}/', [ProductController::class, 'getAction']);
$routes->put('/api/v1/products/{id}/', [ProductController::class, 'updateAction']);
$routes->delete('/api/v1/products/{id}/', [ProductController::class, 'deleteAction']);
```

### Entity (Bitrix ORM)

```php
<?php

declare(strict_types=1);

namespace Rebit\Wallet\Domain\Product\Entity;

use Bitrix\Main\ORM\Objectify\EntityObject;

/**
 * @see ProductTable
 *
 * @property int $ID
 * @property string $NAME
 * @property int $PRICE
 */
class Product extends Product_EO
{
    // Доменные методы поверх Bitrix ORM
}
```

### Использование в контроллере

```php
// Получение — Entity загружается автоматически по {id} из URL
public function getAction(Product $product): ControllerJson
{
    return $this->json($this->getUseCase->execute($product));
}

// Обновление — Entity + RequestDto в комбинации невозможны в одном action.
// Передавайте ID через RequestDto:
public function updateAction(ProductUpdateRequestDto $dto): ControllerJson
{
    return $this->json($this->updateUseCase->execute($dto));
}

// Удаление — только Entity, дополнительных данных не нужно
public function deleteAction(Product $product): HttpResponse
{
    $this->deleteUseCase->execute($product->getId());

    return $this->noContent();
}
```

Запрос `DELETE /api/v1/products/42/` → маппер извлечёт `id = 42` из URL, загрузит `Product` через ORM и передаст в action.

## Автомаппинг коллекции (массив однородных элементов)

Когда тело запроса — корневой JSON-массив `[{...}, {...}, ...]`, используется `RequestToCollectionMapper`.

Для этого нужно:
1. Создать **DTO элемента** — `final readonly class`, реализующий `RequestDtoInterface`.
2. Создать **коллекцию** — `final readonly class`, наследующую `AbstractRequestCollection`, с методом `getItemClass()`.
3. Указать коллекцию как тип параметра action-метода контроллера.

### DTO элемента

```php
<?php

declare(strict_types=1);

namespace Rebit\Wallet\Application\Product\Dto;

use Rebit\Share\Application\Interface\RequestDtoInterface;
use Symfony\Component\Validator\Constraints as Assert;

final readonly class ProductImportItemRequestDto implements RequestDtoInterface
{
    public function __construct(
        #[Assert\NotNull]
        #[Assert\Type('string')]
        public string $name,
        #[Assert\NotNull]
        #[Assert\Type('integer')]
        #[Assert\GreaterThan(0)]
        public int $price,
    ) {}
}
```

### Коллекция

```php
<?php

declare(strict_types=1);

namespace Rebit\Wallet\Application\Product\Dto;

use Rebit\Share\Application\Collection\AbstractRequestCollection;

/**
 * @extends AbstractRequestCollection<ProductImportItemRequestDto>
 */
final readonly class ProductImportCollection extends AbstractRequestCollection
{
    public static function getItemClass(): string
    {
        return ProductImportItemRequestDto::class;
    }
}
```

### Использование в контроллере

```php
public function importAction(ProductImportCollection $collection): HttpResponse
{
    $this->importUseCase->execute($collection);

    return $this->created();
}
```

Тело запроса:
```json
[
    {"name": "Стельки ортопедические", "price": 1500},
    {"name": "Бандаж коленный", "price": 3200}
]
```

Маппер автоматически:
- Парсит JSON-массив из тела запроса
- Создаёт `ProductImportItemRequestDto` для каждого элемента через `ArrayToDtoMapper::mapList()`
- Оборачивает массив DTO в `ProductImportCollection`
- Валидация `#[Assert\...]` применяется к каждому элементу

Коллекция реализует `IteratorAggregate` и `Countable` — можно использовать в `foreach` и `count()`.
