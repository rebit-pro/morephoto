# Комментарии в коде

## Введение

Хорошо написанный код должен быть самодокументированным, то есть его логика должна быть понятна из названий классов, методов и переменных. Однако бывают ситуации, когда название не передает всей необходимой информации или в коде присутствуют неочевидные решения. В таких случаях **обязательно добавляйте комментарии**, чтобы объяснить сложные или неочевидные моменты.

## Когда нужно комментировать?

### 1. Неочевидные решения

Если в коде используется "костыль" (временное решение, обходной путь) или специфическая логика, которая не очевидна из названий, обязательно добавьте комментарий.

#### Пример:

```php
// Bitrix ORM не поддерживает LEFT JOIN в версии 8.3,
// поэтому получаем ID элементов, а затем ищем в другой таблице
$elementIds = UserTable::query()
    ->setSelect(['ID'])
    ->exec();
```

### 2. Особенности работы сторонних систем

Если код зависит от внешних систем (например, сторонние API, базы данных или фреймворки), уточните особенности их работы.

#### Пример:

```php
// Elasticsearch возвращает результаты постранично, индекс страницы начинается с 0
$results = $elasticClient->search([
    'from' => ($page - 1) * $pageSize,  // from для Elasticsearch, а не для SQL
    'size' => $pageSize,
]);
```

### 3. Временные решения и прочие TODO

Если код является временным и планируется его переписать или удалить, укажите это в комментарии.

#### Пример:

```php
// TODO: после миграции на новую версию Bitrix заменить на ORM
$result = \COption::GetOptionString('module_id', 'option_name', 'default');

// TODO: эта функция работает неправильно при quantity > 1000
// см. https://jira.example.com/browse/TASK-123
public function calculateDiscount(int $quantity): float {
    // ...
}
```

### 4. Сложная логика

Если алгоритм сложный и его трудно понять из кода, добавьте пояснение.

#### Пример:

```php
// Проверяем, что товар в топе категории (top 10 по рейтингу и количеству отзывов)
// сначала по рейтингу, потом по количеству отзывов, чтобы исключить spam
$topProducts = $products
    ->filter(static fn(Product $p): bool => $p->getRating() >= 4.5 && $p->getReviewCount() > 50)
    ->sort(static fn(Product $a, Product $b): int =>
        $b->getRating() <=> $a->getRating() ?:
        $b->getReviewCount() <=> $a->getReviewCount()
    );
```

### 5. Особые условия использования

Если метод или функция требует определенных условий для корректной работы, уточните это.

#### Пример:

```php
/**
 * Важно: метод работает только внутри транзакции БД.
 * Если вызвать вне транзакции - результаты могут быть неконсистентными.
 */
private function updateCategoryCache(int $categoryId): void
{
    // ...
}
```

### 6. Почему выбрано такое решение?

Иногда выбор решения может казаться странным. Объясните, почему именно этот подход был использован.

```php
// Используем while + unset вместо array_filter, потому что:
// 1. array_filter создает новый массив (лишняя память для больших списков)
// 2. в hot path критична скорость выполнения
while ($item = current($items)) {
    if (!$item->isActive()) {
        unset($items[key($items)]);
    }
    next($items);
}
```

## Как правильно писать комментарии?

1. **Будьте краткими**: Комментарий должен быть лаконичным, но содержательным.
2. **Избегайте очевидного**: Не пишите комментарии, которые просто повторяют название метода.
3. **Объясняйте "почему", а не "что"**: Код показывает что происходит, комментарий должен объяснить почему.
4. Если не можете сформулировать комментарий сами - попросите нейросеть помочь.
