# Frontend: список материалов для дизайнера и shortlist фич из Berry

Дата: 2026-03-26

## Цель

Зафиксировать два практических результата:

1. стартовый список картинок, иллюстраций и инфографики, которые стоит заказать у дизайнера;
2. shortlist компонентов и UI-паттернов из шаблона `Berry`, которые реально полезны для `Rebit`, без переноса шаблона целиком.

## 1. Короткий вывод

Текущий фронт уже использует Berry как shell, поэтому возвращать нужно не демо-страницы, а только прикладные reusable-паттерны.

Самое полезное на ближайший этап:

1. `shared`-обёртки карточек и таблиц;
2. единый `empty state`;
3. table-pattern для списков и истории;
4. чатовый layout как основа для будущих деталей сделки;
5. точечные `labs`-компоненты под реальные сценарии (`VMaskInput`, `VFileUpload`).

Отдельно: по продуктовым сценариям проекту скоро понадобятся экраны сделки, статусы сделки, чат сделки, автоскрипты сообщений и более сильные empty/error/loading states. Поэтому уже сейчас есть смысл синхронизировать дизайнерский backlog с техническим shortlist.

**Где понадобится:**

## 3. Что ещё стоит сразу попросить у дизайнера кроме картинок

Это уже не иллюстрации, но очень полезные дизайн-артефакты для фронта:

1. **статусные бейджи сделки** — цвета, фоны, состояния hover/disabled;
2. **шаблон системного сообщения в чате** — например: «Сделка создана», «Покупатель отметил оплату», «Сделка завершена»;
3. **шаблон карточки сделки** — desktop + mobile;
4. **пустые состояния для таблиц**;
5. **компактные иконки для payment methods**;
6. **паттерн таймера сделки** — normal / warning / critical.

На практике эти артефакты дадут фронту больше пользы, чем одна большая hero-иллюстрация.

## 4. Полезные фичи и компоненты из Berry для текущего проекта

Ниже — не повтор всего `docs/frontend-berry-template-analysis.md`, а только то, что имеет прикладной смысл именно сейчас.

## 4.1. Shared card wrappers

**Файлы в Berry:**

- `src/components/shared/UiParentCard.vue`
- `src/components/shared/UiTableCard.vue`
- `src/components/shared/WidgetCard.vue`
- `src/components/shared/WidgetCardv2.vue`

**Почему подходит проекту:**

Сейчас в проекте много прямой разметки на `v-card`, а папка `frontend/src/components/shared/` пустая. Это хороший сигнал, что reusable UI-слой ещё не выделен.

**Где применить:**

- `DashboardPage.vue`
- `TransactionsPage.vue`
- `ApiConnectionPage.vue`
- будущие страницы сделок, объявлений, статистики

**Как использовать правильно:**

- не копировать Berry 1-в-1;
- сделать свои проектные обёртки с нормальными слотами: `title`, `actions`, `subtitle`, `default`;
- сразу учитывать мобильную вёрстку и единые отступы.

**Вердикт:**

`must have`, низкая цена внедрения.

---

## 4.2. Единый empty state

**Источник в Berry:**

- `src/views/ui-elements/advance/UiEmptyState.vue`

**Что полезно:**

Не сама demo-страница, а паттерн использования `v-empty-state` и единый способ оформлять пустые состояния.

**Где применить в Rebit:**

- нет API-ключа;
- нет ордеров в стакане;
- нет транзакций;
- нет балансов;
- нет активных сделок;
- нет скриптов автосообщений;
- нет сообщений в чате.

**Что лучше сделать:**

Создать свой `AppEmptyState.vue` и централизовать:

- icon / image;
- headline;
- supporting text;
- actions;
- компактный и обычный режим.

**Вердикт:**

`must have`, особенно если параллельно готовим дизайнерские иллюстрации.

**Источники в Berry:**

**Вердикт:**

`must have`, но как собственная реализация, а не как перенос demo-страниц.

## 4.4. Чат из Berry — полезен как reference для деталей сделки

**Файлы в Berry:**

- `src/views/apps/chats/ChatPage.vue`
- `src/components/apps/chats/ChatDetail.vue`
- `src/components/apps/chats/ChatSendMsg.vue`
- `src/components/apps/chats/ChatListing.vue`
- `src/components/apps/chats/ChatInfo.vue`
- `src/components/apps/chats/ChatProfile.vue`

**Почему это важно именно для Rebit:**

По доменной модели и пользовательским сценариям у проекта есть:

- `Trade`;
- `TradeChat`;
- `TradeMessage`;
- `TradeChatScript`;
- статусы сделки;
- режим чата «только чтение» после завершения/отмены.

То есть чат здесь не декоративный модуль, а часть жизненного цикла сделки.

### Что реально стоит взять из Berry

1. **layout из 2–3 колонок**
   - слева список/контекст;
   - в центре сам чат;
   - справа info drawer.

2. **разделение на отдельные компоненты**
   - header чата;
   - message list;
   - composer;
   - info sidebar.

3. **scrollable message area**
   - у проекта уже подключён `PerfectScrollbar`, значит интеграция дешёвая.

4. **composer-паттерн**
   - поле ввода;
   - attach/send actions;
   - disabled/read-only режим при закрытой сделке.

5. **mobile drawer behaviour**
   - на мобилке список сделок/контекст должен открываться через drawer, а не занимать весь экран.

### Что нельзя переносить 1-в-1

1. demo-store с фейковыми чатами;
2. user presence (`online/away/busy`) в текущем виде;
3. кнопки audio/video call;
4. мессенджерную механику, не связанную со сделкой.

### Как это лучше адаптировать в Rebit

Вместо общего chat-app сделать доменные компоненты:

- `TradeDetailHeader`
- `TradeStatusTimeline`
- `TradeMessageList`
- `TradeMessageComposer`
- `TradeInfoSidebar`
- `TradeSystemMessage`
- `TradeScriptBadge` или `TradeScriptPanel`

### Дополнительная польза

Berry-чат хорошо подходит как visual reference для будущих деталей сделки, потому что там уже есть:

- header + actions;
- отдельная scroll-зона;
- drawer для деталей;
- понятный split layout.

Именно это и нужно сделке P2P, только в предметной адаптации.

**Вердикт:**

`высокий приоритет как reference`, но не переносить как готовый модуль.

## 4.6. Vuetify Labs-компоненты, которые реально пригодятся

**Смотрел в Berry:**

- `VMaskInput`
- `VFileUpload`
- `VFileUploadItem`
- `VPie`
- `VCalendar`

### Что стоит рассматривать

#### `VMaskInput`

Подойдёт для:

- телефонов;
- банковских реквизитов;
- платёжных данных;
- ограниченных форм ввода.

#### `VFileUpload`

Подойдёт для:

- вложений в чат сделки;
- подтверждений оплаты;
- KYC/документов, если такой сценарий появится.

### Что пока не нужно

- `VPie` — пока нет подтверждённой аналитики, где это критично;
- `VCalendar` — сейчас не выглядит как ближайшая потребность.

**Вердикт:**

`возвращать только под конкретный use case`.

## 4.8. Snackbar / inline feedback patterns

**Источник:**

- `UiSnackbar.vue`

**Почему полезно:**

В проекте много операций с коротким циклом обратной связи:

- API подключён;
- статус проверен;
- сообщение в чат отправлено;
- платёж подтверждён;
- история обновлена;
- фильтры сброшены.

Для этого нужен единый проектный паттерн toast/snackbar, чтобы не плодить локальные алерты внутри каждой страницы.

**Вердикт:**

`средний приоритет`, но ценность высокая после появления экранов сделки.

## 5. Что из Berry не нужно тянуть в проект

Не стоит возвращать:

1. целые demo apps (`mail`, `kanban`, ecommerce и т.д.);
2. auth flow из Berry;
3. heavy dashboard widgets с фейковыми метриками;
4. audio/video/chat-функции, не связанные со сделкой;
5. большой template infrastructure ради одной UI-фичи.

Для Rebit сейчас важнее предметный UI, чем «богатый шаблон».
