# Логирование

Эта глава описывает, как оформлять логирование в новом коде и в переходных legacy-точках проекта.

## 1. Базовое правило проекта

- в новом `UseCase`, application service, command и infrastructure-сервисе используют `LoggerInterface` через конструктор;
- `Log` facade это переходный статический вход, допустимый в DI-конфигах и legacy, а также временных //TODO решениях;
- логирование обычно относится к Application/Infrastructure-слою, его не должно быть в Domain-слое.

## 2. Быстрая карта

| Инструмент | Тип | Для чего нужен                               |
|---|---|----------------------------------------------|
| `LoggerInterface` | контракт | основной способ логирования в новом коде     |
| `Log` | facade | получить logger по каналу или default logger |
| `LogChannelEnum` | enum | выбрать канал логирования                    |

## 3. `Log` facade

Полное имя: `Rebit\Share\Shared\Facade\Log`

`Log` это проектный статический вход в Monolog-логгер.
Он нужен в тех местах, где проект уже опирается на статическую выдачу логгера:

- DI-конфиги;
- legacy;

### Публичный API

| Метод | Что делает |
|---|---|
| `setLogger(LoggerInterface $logger): void` | подменяет default logger |
| `channel(LogChannelEnum $channel): LoggerInterface` | возвращает логгер конкретного канала |
| `getLogger(LogChannelEnum $default = LogChannelEnum::default): LoggerInterface` | возвращает logger для DI и сервисов |
| `__callStatic(...)` | проксирует PSR-3 методы в default logger |

Через `__callStatic` доступны обычные методы логгера:

- `debug(...)`
- `info(...)`
- `warning(...)`
- `error(...)`
- `critical(...)`
- и остальные PSR-3 уровни.

### Как использовать

В новом коде:

```php
final readonly class FooUseCase
{
    public function __construct(
        private FooGatewayInterface $fooGateway,
        private LoggerInterface $logger,
    ) {}

    public function execute(int $sectionId): array
    {
        $this->logger->info('Получение данных для раздела', [
            'sectionId' => $sectionId,
        ]);

        return $this->fooGateway->getBySection($sectionId);
    }
}
```

В DI:

```php
return [
    ReindexFacetUseCase::class => [
        'className' => ReindexFacetUseCase::class,
        'constructorParams' => static function(): array {
            return [
                ServiceLocator::getInstance()->get(FacetReindexerInterface::class),
                ServiceLocator::getInstance()->get(FacetAppService::class),
                Log::getLogger(LogChannelEnum::catalog),
            ];
        },
    ],
];
```

В legacy:

```php
Log::channel(LogChannelEnum::medical)->info('Получение расписания из МИС3', $context);
Log::error('Не смог получить бонусную карту для пользователя.', ['userId' => $userId]);
```

## 4. Каналы `LogChannelEnum`

Каналы задаются через `LogChannelEnum`:

| Канал | Когда использовать |
|---|---|
| `default` | общий логгер по умолчанию |
| `catalog` | каталог |
| `medical` | medical |
| `cli` | CLI-команды |
| `todo` | временные warning/info для оценки и переходных мест |
| `payment` | платёжный контур |
| `import` | импорты |
| `imshop` | imshop-интеграции |

Если канал важен по смыслу, выбирайте его явно через `Log::channel(...)` или через инъекцию уже подготовленного logger.

## 5. Где логирование уместно

### Когда лог нужен

- в `UseCase`, если нужно зафиксировать orchestration-событие: внешний вызов, fallback, деградацию, recoverable-ошибку;
- в infrastructure-адаптере, если нужно записать технический контекст до оборачивания исключения;
- в CLI и интеграционных сценариях, где важно видеть этапы выполнения и итог.

### Когда лог не нужен

- внутри entity, value object, enum и другой domain-логики;
- вместо нормальной обработки ошибки, валидации или возврата результата;
- в плотных циклах и hot path без диагностической пользы;
- для сырых payload без фильтрации, если в них нет операционной ценности.

## Что нужно запомнить

1. В новом коде логгер инжектируется через `LoggerInterface`; `Log` остаётся для статических и legacy-точек.
2. Если канал предметно важен, задавайте его явно через `LogChannelEnum`.
3. Логирование это часть orchestration и infrastructure, а не domain-правило.
4. Лог должен помогать диагностике, а не дублировать каждую штатную ветку выполнения.
