# Архитектурное руководство Rebit P2P

Это подробное руководство по архитектуре проекта Rebit P2P.
Оно не просто перечисляет правила, а объясняет:

- какие архитектурные подходы используются;
- почему они нужны;
- как выбирать слой и паттерн;
- как выглядят правильные решения в коде;
- где проект допускает переходные или legacy (исторические) отклонения.

Правила оформления кода (нейминг, типизация, phpDoc, форматирование) описаны отдельно в [Правилах написания кода](../code-writing-rules/README.md).


> **Примечание:** в примерах кода могут использоваться иллюстративные доменные имена
> (`Product`, `Facet`, `SmartFilter`, `Salon`, `Banner` и т.д.).
> В реальном проекте домены: `Transaction`, `Balance`, `ApiConnection`, `User`, `Auth`.
> Примеры демонстрируют архитектурные паттерны — адаптируйте имена под свой домен.

## Основная идея этой документации

Каждый раздел отвечает на четыре вопроса:

1. Что означает понятие.
2. Зачем оно нужно.
3. Как его применять в нашем проекте.
4. Как выглядит правильный код.

## Как устроены главы

Большинство глав собраны по одному шаблону:

1. Определение понятия простыми словами.
2. Объяснение, зачем оно нужно.
3. Правила применения в проекте.
4. Таблицы, схемы и примеры кода.
5. Краткий блок «Что нужно запомнить».

Если в реальном коде встречается legacy-отклонение, оно упоминается отдельно и не подаётся как норма для нового кода.
