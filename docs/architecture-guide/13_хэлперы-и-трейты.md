# `rebit.share`: хэлперы и трейты

Логирование вынесено в [отдельную главу](./12_логирование.md).

Внутри этой главы:

- статические utility-классы для DTO, request, serialization и мелких преобразований;
- маленькие project helpers;
- трейты для install Bitrix-модулей.

## 1. Быстрая карта

| Класс | Тип | Для чего нужен |
|---|---|---|
| `ArrayToDtoMapper` | utility | гидрация массива в DTO с валидацией |
| `JsonSerializerHelper` | helper | создание дефолтного serializer/normalizer и JSON-сериализация |
| `NormalizerHelper` | helper | быстро нормализовать данные в массив |
| `RequestHelper` | helper | собрать входные данные запроса и построить URL |
| `ValidationHelper` | helper | валидация DTO через Symfony Validator |
| `StringHelper` | helper | маленькие string/int utility-операции |
| `PathHelper` | helper | преобразование абсолютного пути в относительный |
| `ModuleHelper` | module utility | проверить, что модуль установлен |
| `RequestLocalEventStateStore` | event utility | временно хранить integration-state между парными Bitrix-событиями одного запроса |
| `ModuleComponentInstallerTrait` | trait | установка и удаление компонентов модуля |
| `ModuleRoutingTrait` | trait | подключение маршрутов модуля в Bitrix |

## 2. DTO, request и serialization utilities

### `ArrayToDtoMapper`

Полное имя: `Rebit\Share\Shared\Helper\ArrayToDtoMapper`

Это не просто «мелкий helper», а базовая utility для маппинга request/array в DTO.

Публичный API:

| Метод | Что делает |
|---|---|
| `map(array $data, string $className): object` | строит один DTO |
| `mapList(array $data, string $className): array` | строит список DTO |

Что делает автоматически:

- переименовывает поля по `#[SerializedName(...)]`;
- отбрасывает лишние поля;
- пишет warning в `todo`, если пришли лишние поля;
- валидирует DTO через Symfony Validator;
- использует metadata cache через `DtoMetadataService`.

Использовать руками стоит только там, где реально нужен ручной array-to-dto mapping.
Если вы уже находитесь в controller mapping infrastructure, этот слой чаще всего вызывает его сам.

### `ValidationHelper`

Полное имя: `Rebit\Share\Infrastructure\Helpers\ValidationHelper`

Публичный API:

| Метод | Что делает |
|---|---|
| `validate(DtoInterface $dto): void` | валидирует DTO и бросает `ValidationHttpException` |

Используйте, если нужно отдельно провалидировать DTO вне стандартного request-mapper.

### `RequestHelper`

Полное имя: `Rebit\Share\Infrastructure\Helpers\RequestHelper`

Публичный API:

| Метод | Что делает |
|---|---|
| `collectRequestValues(HttpRequest $request): array` | собирает GET + JSON или GET + POST |
| `getSiteUrl(): string` | возвращает `scheme://host` |
| `getFullUrl(string $pageUri = '/'): string` | строит полный URL или возвращает внешний URL как есть |

Нюансы:

- если в запросе есть JSON body, helper не смешивает его с POST;
- при совпадении ключей тело запроса побеждает GET;
- `getFullUrl()` считает URL внешним, если в нём уже есть домен проекта.

### `JsonSerializerHelper`

Полное имя: `Rebit\Share\Infrastructure\Helpers\JsonSerializerHelper`

Публичный API:

| Метод / константа | Что делает |
|---|---|
| `DEFAULT_JSON_OPTIONS` | дефолтные флаги `json_encode` |
| `createDefaultNormalizer(): NormalizerInterface` | создаёт стандартный normalizer |
| `createDefaultSerializer(): SerializerInterface` | создаёт `CommonSerializer` |
| `serialize(NormalizerInterface $normalizer, mixed $data, int $jsonOptions = self::DEFAULT_JSON_OPTIONS): string` | нормализует и сериализует в JSON |

Используйте, если нужен явный serializer/normalizer вне готового controller stack.

### `NormalizerHelper`

Полное имя: `Rebit\Share\Infrastructure\Helpers\NormalizerHelper`

Публичный API:

| Метод | Что делает |
|---|---|
| `normalize(mixed $data): mixed` | нормализует данные через общий normalizer |

Это тонкая статическая обёртка.
Подходит, когда serializer-объект отдельно не нужен и нужен только normalized array/value.

## 3. Простые project helpers

### `StringHelper`

Полное имя: `Rebit\Share\Shared\Helper\StringHelper`

Публичный API:

| Метод | Что делает |
|---|---|
| `stringToIntArray(string $string): array` | превращает строку вида `-1, 3.000, 4` в `int[]` |

Нюансы:

- пустая строка даёт `[]`;
- принимает только целые числа и дробные с нулями после точки;
- невалидный формат бросает `InvalidArgumentException`.

### `PathHelper`

Полное имя: `Rebit\Share\Shared\Helper\PathHelper`

Публичный API:

| Метод | Что делает |
|---|---|
| `getRelativePath(string $fullPath): string` | отрезает `Application::getDocumentRoot()` от абсолютного пути |

Подходит для инфраструктуры, файловых операций и генерации путей внутри проекта.

### `ModuleHelper`

Полное имя: `Rebit\Share\Infrastructure\Bitrix\Module\ModuleHelper`

Публичный API:

| Метод | Что делает |
|---|---|
| `validateModuleInstalled(string $moduleName): void` | проверяет, что модуль установлен |

Нюанс:

- в admin section исключение не бросается, чтобы не ломать установку и работу админки.

Используется в `include.php` модулей вроде `rebit.wallet`, `rebit.identity`, `rebit.bybit`.

### `RequestLocalEventStateStore`

Полное имя: `Rebit\Share\Infrastructure\Event\RequestLocalEventStateStore`

Это не project helper общего назначения, а узкая utility для `Infrastructure/Event`.

Публичный API:

| Метод | Что делает |
|---|---|
| `remember(string $scope, int|string $entityId, mixed $state): void` | сохраняет raw-state по scope и id сущности |
| `pull(string $scope, int|string $entityId): mixed` | одноразово читает и сразу удаляет сохранённое состояние |
| `clear(?string $scope = null): void` | очищает конкретный scope или всё временное хранилище |

Использовать только когда одновременно выполняются все условия:

- есть парные `OnBefore...` / `OnAfter...` события в рамках одного PHP-запроса;
- в `OnAfter...` нужен old-state для сравнения с new-state;
- старое состояние нельзя надёжно получить без временного хранения;
- хранение в кеше, Redis или БД для такого сценария избыточно.

Не использовать:

- как предметный кеш;
- как shared-state между воркерами, cron-задачами и очередями;
- в `UseCase`, domain или application-логике;
- для хранения DTO, entity и уже принятого бизнес-решения.

Сценарий использования в Bitrix-событиях разобран в [14_bitrix-события.md](./14_bitrix-события.md).

## 4. Traits для Bitrix-модулей

### `ModuleComponentInstallerTrait`

Полное имя: `Rebit\Share\Infrastructure\Bitrix\Module\ModuleComponentInstallerTrait`

Это trait для `install/index.php` модулей, которые ставят Bitrix-компоненты.

Публично используемый API:

| Метод | Что делать разработчику |
|---|---|
| `initModuleComponentInstaller(): void` | вызвать в конструкторе модуля |
| `installComponents(): void` | вызвать из `DoInstall()` |
| `uninstallComponents(): void` | вызвать из `DoUninstall()` |

Что он делает:

- берёт компоненты из `local/modules/<module>/install/components`;
- копирует их в `/bitrix/components/rebit`;
- при uninstall удаляет только компоненты этого модуля.

Обязательное условие:

- у класса должен быть `MODULE_ID`.

### `ModuleRoutingTrait`

Полное имя: `Rebit\Share\Infrastructure\Bitrix\Module\ModuleRoutingTrait`

Это trait для модулей, которые публикуют `routes.php`.

Публично используемый API:

| Метод | Что делать разработчику |
|---|---|
| `initModuleRouting(): void` | вызвать в конструкторе модуля |
| `installModuleRouting(): void` | вызвать при установке |
| `uninstallModuleRouting(): void` | вызвать при удалении |

Что он делает:

- проверяет наличие `routes.php` в модуле;
- создаёт symlink в `/local/routes/<module>.php`;
- регистрирует маршрутный файл в конфигурации Bitrix через `Configuration`.

Используйте trait только в module install layer.
Это не инструмент для прикладной логики.

## 5. Правила использования

### Когда эти инструменты уместны

- `ArrayToDtoMapper`, `RequestHelper`, `ValidationHelper` в controller/request infrastructure;
- `JsonSerializerHelper` и `NormalizerHelper` в serialization layer;
- `StringHelper` и `PathHelper` для маленьких stateless-операций;
- `RequestLocalEventStateStore` только в `Infrastructure/Event` для парных `before/after` событий одного запроса;
- module traits только в `install/index.php` и bootstrap модуля.

### Когда они неуместны

- вместо нормального `UseCase` или application service;
- вместо domain-логики;
- как способ спрятать зависимости, если можно честно инжектировать сервис через конструктор;
- `RequestLocalEventStateStore` вне integration-сценария с парными событиями одного запроса;
- traits вне module/install/infrastructure слоя.

## Что нужно запомнить

1. После вынесения кэша и логирования в отдельные главы этот раздел описывает остальные utility-инструменты из `rebit.share`.
2. Главный mapper utility здесь это `ArrayToDtoMapper`.
3. `RequestHelper`, `ValidationHelper`, `JsonSerializerHelper` и `NormalizerHelper` относятся к controller/infrastructure слою, а не к бизнес-логике.
4. `RequestLocalEventStateStore` это узкая event utility для временного integration-state внутри одного запроса.
5. `ModuleComponentInstallerTrait` и `ModuleRoutingTrait` используются только в module install/bootstrap коде.
6. Если задача требует предметного правила, это уже не helper и не trait, а нормальный слой архитектуры.
