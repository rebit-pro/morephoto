# Отчёт: Недостающие API-эндпоинты

Дата: 2026-03-26

## Контекст
На основании анализа сценариев (`docs/scenario.md`) и текущей Postman-коллекции
(`docs/review/rebit-wallet-exchange-postman.json`) выявлены эндпоинты, которых не хватает
для полной реализации пользовательских сценариев.

---

## 1. `PATCH /api/v1/exchange/advertisements/:id` — Запуск/Остановка объявления

**Сценарий:** 6 (Создание собственного ордера), а также общее управление объявлениями.

**Проблема:** В Postman-коллекции есть только:
- `GET /api/v1/exchange/advertisements` — получение списка
- `POST /api/v1/exchange/advertisements` — создание
- `DELETE /api/v1/exchange/advertisements/:id` — удаление (деактивация)

Для реализации **запуска/остановки** объявления без удаления нужен эндпоинт,
позволяющий переключать статус `active` ↔ `paused`.

**Предложение:**
```
PATCH /api/v1/exchange/advertisements/:id
Body: { "status": "active" | "paused" }
```

Альтернатива: два отдельных POST-эндпоинта:
```
POST /api/v1/exchange/advertisements/:id/activate
POST /api/v1/exchange/advertisements/:id/pause
```

---

## 2. `GET /api/v1/exchange/advertisements/:id` — Детали одного объявления

**Сценарий:** 6, 12.3 (привязка скрипта к объявлению).

**Проблема:** Для редактирования объявления или просмотра деталей нужно получить
конкретное объявление по ID. Сейчас можно получить только список.

**Предложение:**
```
GET /api/v1/exchange/advertisements/:id
```

---

## 3. `PATCH /api/v1/exchange/advertisements/:id` — Редактирование объявления

**Сценарий:** 6, 12.3 (изменение chatScriptId у объявления).

**Проблема:** Невозможно отредактировать параметры объявления (цену, лимиты,
привязку скрипта) без удаления и пересоздания.

**Предложение:**
```
PATCH /api/v1/exchange/advertisements/:id
Body: { ...partial fields... }
```

---

## 4. `POST /api/v1/exchange/trades` — Инициация сделки из стакана (deep link)

**Сценарий:** 3 (Покупка по предложению из стакана).

**Проблема:** Согласно сценарию 3, создание сделки через Bybit API **невозможно**
(ограничение Bybit). Пользователь перенаправляется на Bybit. Однако для
формирования deep link может потребоваться серверный эндпоинт, который:
- Генерирует корректный URL Bybit
- Начинает polling для обнаружения новой сделки

**Статус:** Возможно, это не API-эндпоинт, а утилитная функция на фронтенде.
Требуется уточнение.

---

## 5. `GET /api/v1/wallet/currencies` или расширение `GET /api/v1/exchange/currencies`

**Сценарий:** 5 (Просмотр личного кабинета — фильтрация транзакций по валюте).

**Проблема:** Для фильтра транзакций по `currencyId` нужен справочник валют
с ID. Эндпоинт `GET /api/v1/exchange/currencies` существует, но он в модуле exchange.
Для wallet-модуля может потребоваться собственный справочник или согласование,
что exchange-справочник используется кросс-модульно.

**Статус:** Низкий приоритет — можно использовать `GET /api/v1/exchange/currencies`.

---

## 6. `GET /api/v1/wallet/reports/cash-flow` — Отчёт оборотов денежных средств

**Сценарий:** 5 (вкладка «Статистика»).

**Проблема:** Для полноценного отчёта по оборотам необходим серверный эндпоинт
с агрегацией данных (группировка по периодам, подсчёт входящих/исходящих оборотов,
сальдо).

**Предложение:**
```
GET /api/v1/wallet/reports/cash-flow?period=day|week|month&dateFrom=&dateTo=&currencyId=
Response: {
  "data": {
    "items": [
      {
        "period": "2026-03-01",
        "incoming": "15000.00",
        "outgoing": "8500.00",
        "balance": "6500.00"
      }
    ],
    "totals": {
      "incoming": "45000.00",
      "outgoing": "25500.00",
      "balance": "19500.00"
    }
  }
}
```

**Статус:** Фронтенд-заглушка создана. Бэкенд-эндпоинт необходим.
