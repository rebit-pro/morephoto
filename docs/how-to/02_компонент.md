# HOW TO: сделать компонент

> ⚠️ **В текущей версии проекта Rebit P2P Bitrix-компоненты с шаблонами не используются.**
> Фронтенд реализован на Vue 3 + TypeScript + Vite (SPA).
> Этот раздел сохранён как справочный на случай, если компоненты понадобятся в будущем.

## 1. Создайте дерево папок

В модуле:

```text
local/modules/
`-- rebit.<module>/
    |-- install/
    |   `-- components/
    |       `-- <component-code>/
    |           `-- class.php
    `-- lib/
        `-- Presentation/
            `-- Component/
                `-- <Component>/
                    |-- Dto/
                    |   |-- <Component>ComponentParamsDto.php
                    |   `-- <Component>ComponentResultDto.php
                    |-- ViewModel/
                    |   `-- <Component>ViewModel.php
                    `-- <Component>Builder.php
```

В шаблоне сайта:

```text
local/templates/
`-- <site-template>/
    `-- components/
        `-- rebit/
            `-- <component-code>/
                `-- .default/
                    `-- template.php
```

`<site-template>` обычно один из:

- `.default`
- `rebit_desktop`
- `rebit_mobile`

Пример реальных имен:

```text
local/modules/
`-- rebit.wallet/
    |-- install/components/catalog.section.fast/class.php
    `-- lib/Presentation/Component/CatalogSection/
        |-- Dto/CatalogSectionComponentParamsDto.php
        |-- Dto/CatalogSectionComponentResultDto.php
        |-- CatalogSectionBuilder.php
        `-- ViewModel/CatalogSectionViewModel.php
```

## 2. Создайте код в модуле

Минимальный набор:

```text
local/modules/
`-- rebit.<module>/
    |-- install/
    |   `-- components/
    |       `-- <component-code>/
    |           `-- class.php
    `-- lib/
        `-- Presentation/
            `-- Component/
                `-- <Component>/
                    |-- Dto/
                    |   |-- <Component>ComponentParamsDto.php
                    |   `-- <Component>ComponentResultDto.php
                    |-- ViewModel/
                    |   `-- <Component>ViewModel.php
                    `-- <Component>Builder.php
```

`class.php` должен быть тонким:

- вернуть класс Builder
- вернуть класс Params DTO
- вернуть ViewModel (если есть шаблон, а в простейших случаях можно без ViewModel)
- почти всегда вернуть класс `ExceptionResolver`
- не содержать больше ничего

Пример `class.php`:

```php
<?php

declare(strict_types=1);

use Rebit\Example\Presentation\Component\Example\Dto\ExampleComponentParamsDto;
use Rebit\Example\Presentation\Component\Example\Dto\ExampleComponentResultDto;
use Rebit\Example\Presentation\Component\Example\ExceptionResolver\ExampleExceptionResolver;
use Rebit\Example\Presentation\Component\Example\ExampleBuilder;
use Rebit\Example\Presentation\Component\Example\ViewModel\ExampleViewModel;
use Rebit\Share\Infrastructure\Bitrix\AbstractDtoComponent;
use Rebit\Share\Infrastructure\Interface\HasViewModelInterface;

if (!defined('B_PROLOG_INCLUDED') || true !== B_PROLOG_INCLUDED) {
    exit;
}

/**
 * @extends AbstractDtoComponent<ExampleComponentParamsDto, ExampleComponentResultDto, ExampleBuilder>
 */
final class ExampleComponent extends AbstractDtoComponent implements HasViewModelInterface
{
    protected function getBuilderClass(): string
    {
        return ExampleBuilder::class;
    }

    protected function getParamsDtoClass(): string
    {
        return ExampleComponentParamsDto::class;
    }

    public function getViewModel(): ExampleViewModel
    {
        return new ExampleViewModel($this);
    }

    protected function getExceptionResolverClass(): string
    {
        return ExampleExceptionResolver::class;
    }
}
```

Для новых компонентов метод `getExceptionResolverClass()` почти всегда нужно переопределять.
Не переопределять его можно только как редкое осознанное исключение, когда компонент действительно должен пробрасывать ошибку выше без собственной деградации.
Тогда сработает `DefaultComponentExceptionResolver` из `rebit.share` и ошибка будет выведена на странице.

Пример `ParamsDto` и `ResultDto`:

```php
<?php

declare(strict_types=1);

namespace Rebit\Example\Presentation\Component\Example\Dto;

use Rebit\Share\Infrastructure\Context\Dto\CurrentUserDto;
use Rebit\Share\Infrastructure\Bitrix\AbstractComponentParamsDto;
use Rebit\Share\Shared\ValueObject\City;

final readonly class ExampleComponentParamsDto extends AbstractComponentParamsDto
{
    public function __construct(
        public string $cacheType,
        public int $sectionId,
        // Город влияет на выборку, цены, остатки и должен быть явным входом компонента.
        public City $currentCity,
        // Пользователь влияет на персонализацию и тоже должен участвовать в контракте компонента.
        public ?CurrentUserDto $currentUser,
        // Все параметры пагинации и сортировки храним здесь, а не читаем из Request внутри Builder.
        public int $currentPage = 1,
        public string $sort = 'popular',
        public int $pageSize = 12,
    ) {}
}
```

```php
<?php

declare(strict_types=1);

namespace Rebit\Example\Presentation\Component\Example\Dto;

final readonly class ExampleComponentResultDto
{
    /** @param list<string> $items */
    public function __construct(
        public array $items,
        public string $title,
    ) {}
}
```

Важно про `ParamsDto`:

- все входные данные, от которых зависит результат компонента, должны быть перечислены в `ParamsDto`
- это влияет на корректность кэширования: скрытых входов у компонента быть не должно
- это уменьшает ответственность Builder: он только собирает результат из явных параметров и сервисов
- сервисы и UseCase остаются зависимостями конструктора Builder
- данные запроса, текущая страница, сортировка, флаги, контекст фильтра, город, пользователь должны приходить через `ParamsDto`, а не вычисляться внутри Builder

Хорошо:

```php
<?php

declare(strict_types=1);

final readonly class ExampleComponentParamsDto extends AbstractComponentParamsDto
{
    public function __construct(
        public string $cacheType,
        public int $sectionId,
        public City $currentCity,
        public ?CurrentUserDto $currentUser,
        public int $currentPage,
        public string $sort,
        public int $pageSize,
        public bool $showPromo = true,
    ) {}
}
```

Плохо:

```php
<?php

declare(strict_types=1);

final readonly class ExampleBuilder implements ComponentBuilderInterface
{
    public function __construct(
        private GetProductListUseCase $getProductListUseCase,
        private \Bitrix\Main\Request $request,
    ) {}

    public function build(AbstractComponentParamsDto|ExampleComponentParamsDto $params): ?ExampleComponentResultDto
    {
        $currentPage = (int)$this->request->get('page');
        $sort = (string)$this->request->get('sort');

        $items = $this->getProductListUseCase->execute($params->sectionId, $currentPage, $sort);

        return new ExampleComponentResultDto(
            items: $items,
            title: 'Товары',
        );
    }
}
```

Почему это плохо:

- результат зависит от скрытых входов, которых нет в `ParamsDto`
- кэш компонента становится неочевидным и может отдавать неверные данные
- Builder берет на себя лишнюю ответственность по сбору входных данных

## 2.1. Определите политику на непойманные исключения

Для нового компонента почти всегда нужно сразу определить `ExceptionResolver`.
Он фиксирует контролируемую деградацию компонента на границе рендера.

Обычно это нужно, чтобы:

- показать заглушку;
- не рендерить компонент;
- вернуть `404`;
- сделать redirect.

Без resolver-а компонент оставляют только в исключительных случаях:

- компонент обязан падать выше по стеку без собственной деградации;
- это осознанное архитектурное решение, а не забытый шаг при разработке.

Пример resolver-а для заглушки:

```php
<?php

declare(strict_types=1);

namespace Rebit\Example\Presentation\Component\Example\ExceptionResolver;

use Rebit\Share\Shared\Dto\ComponentExceptionResolutionDto;
use Rebit\Share\Shared\Interface\ComponentExceptionResolverInterface;
use Psr\Log\LoggerInterface;

final readonly class ExampleExceptionResolver implements ComponentExceptionResolverInterface
{
    public function __construct(
        private LoggerInterface $logger,
    ) {}

    public function resolve(\Throwable $exception, string $componentName): ComponentExceptionResolutionDto
    {
        $this->logger->error(
            'Ошибка при построении компонента ' . $componentName,
            [
                'componentName' => $componentName,
                'exception' => $exception,
            ],
        );

        return ComponentExceptionResolutionDto::renderFallback(
            templatePath: '/local/templates/.default/components/rebit/shared/example_error.php',
            statusCode: 503,
        );
    }
}
```

`ComponentExceptionResolutionDto` поддерживает 4 действия:

- `renderFallback`
- `skipRender`
- `process404`
- `redirect`

Если URL редиректа известен только внутри builder, бросайте `ComponentRedirectException`,
а не делайте `LocalRedirect()` прямо в builder.

Подробно про механизм:

- [Как обработать непойманное исключение в компоненте](./component-exception-resolver.md)

## 3. Зарегистрируйте Builder в DI

Обычно это `di/Layers/Presentation.php`.

Builder:

- вызывает UseCase из любых доменов
- вызывает свои сервисы из Presentation
- не вызывает больше ничего
- использует только данные из `ParamsDto` как вход компонента
- не глотает ошибки через `return null`

Пример `Builder`:

```php
<?php

declare(strict_types=1);

namespace Rebit\Example\Presentation\Component\Example;

use Rebit\Example\Application\Product\UseCase\GetProductListUseCase;
use Rebit\Example\Presentation\Component\Example\Dto\ExampleComponentParamsDto;
use Rebit\Example\Presentation\Component\Example\Dto\ExampleComponentResultDto;
use Rebit\Share\Infrastructure\Bitrix\AbstractComponentParamsDto;
use Rebit\Share\Shared\Interface\ComponentBuilderInterface;

final readonly class ExampleBuilder implements ComponentBuilderInterface
{
    public function __construct(
        private GetProductListUseCase $getProductListUseCase,
    ) {}

    public function build(AbstractComponentParamsDto|ExampleComponentParamsDto $params): ?ExampleComponentResultDto
    {
        $items = $this->getProductListUseCase->execute(
            sectionId: $params->sectionId,
            currentPage: $params->currentPage,
            sort: $params->sort,
            pageSize: $params->pageSize,
        );

        return new ExampleComponentResultDto(
            items: $items,
            title: 'Товары раздела',
        );
    }
}
```

Если нужен особый сценарий на ошибке:

- не делайте `LocalRedirect()` в builder напрямую;
- не делайте `Tools::process404()` в builder, если это уже policy компонента;
- бросьте исключение выше или преобразуйте его в `ComponentRedirectException`.

Пример DI-регистрации:

```php
<?php

declare(strict_types=1);

use Bitrix\Main\DI\ServiceLocator;
use Rebit\Example\Application\Product\UseCase\GetProductListUseCase;
use Rebit\Example\Presentation\Component\Example\ExampleBuilder;

return [
    ExampleBuilder::class => [
        'className' => ExampleBuilder::class,
        'constructorParams' => static function(): array {
            return [
                ServiceLocator::getInstance()->get(GetProductListUseCase::class),
            ];
        },
    ],
];
```

## 4. Подготовьте установку компонента

Компонент кладется в:

- `api/public/local/modules/rebit.<module>/install/components/<component-code>/`

При установке модуля `ModuleComponentInstallerTrait` копирует его в:

- `/bitrix/components/rebit/<component-code>`

После этого компонент подключается так:

- `rebit:<component-code>`

Пример установки компонента модулем:

```php
<?php

declare(strict_types=1);

use Rebit\Share\Infrastructure\Bitrix\Module\ModuleComponentInstallerTrait;

class Rebit_Example extends CModule
{
    use ModuleComponentInstallerTrait;

    public function __construct()
    {
        $this->MODULE_ID = 'rebit.example';
        $this->initModuleComponentInstaller();
    }

    public function DoInstall(): bool
    {
        RegisterModule($this->MODULE_ID);
        $this->installComponents();

        return true;
    }
}
```

## 5. Сделайте шаблон

Шаблон создавайте в сайте, а не в модуле:

- `local/templates/.default/components/rebit/<component-code>/.default/template.php`
- `local/templates/rebit_desktop/components/rebit/<component-code>/.default/template.php`
- `local/templates/rebit_mobile/components/rebit/<component-code>/.default/template.php`

Если нужен не `.default`, создайте отдельную папку шаблона вместо `.default`.

Правило:

- шаблон работает через ViewModel
- не пишем новую логику на `$arResult` / `$arParams`

Пример `ViewModel`:

```php
<?php

declare(strict_types=1);

namespace Rebit\Example\Presentation\Component\Example\ViewModel;

final readonly class ExampleViewModel
{
    public function __construct(
        public \ExampleComponent $component,
    ) {}

    public function getTitle(): string
    {
        return $this->component->getResultDto()->title;
    }

    /** @return list<string> */
    public function getItems(): array
    {
        return $this->component->getResultDto()->items;
    }
}
```

Пример `template.php`:

```php
<?php

declare(strict_types=1);

if (!defined('B_PROLOG_INCLUDED') || true !== B_PROLOG_INCLUDED) {
    exit;
}

/** @var CBitrixComponentTemplate $this */
/** @var ExampleComponent $component */
$component = $this->getComponent();
$viewModel = $component->getViewModel();
?>
<section class="example-block">
    <h2><?= htmlspecialchars($viewModel->getTitle()) ?></h2>
    <?php foreach ($viewModel->getItems() as $item): ?>
        <div><?= htmlspecialchars($item) ?></div>
    <?php endforeach; ?>
</section>
```

## 6. Подключите компонент на странице

`$APPLICATION->IncludeComponent(...)` всегда пишите многострочно:

```php
$APPLICATION->IncludeComponent(
    'rebit:example.component',
    '',
    $params,
    $component,
);
```

## 7. Не сломайте AJAX

Не оборачивайте тяжелые AJAX-компоненты в `SetViewTarget`.

Для каталога это особенно важно для:

- `catalog.smart.filter.fast`
- `catalog.section.fast`

Их вызывают inline.

Пример inline-подключения:

```php
<?php

$APPLICATION->IncludeComponent(
    'rebit:catalog.smart.filter.fast',
    '',
    $smartFilterParams,
    $component,
);

$APPLICATION->IncludeComponent(
    'rebit:catalog.section.fast',
    '',
    $catalogSectionParams,
    $component,
);
```

## 8. Проверьте перед сдачей

- `class.php` только делегирует
- все входные зависимости, влияющие на результат и кэш, перечислены в `ParamsDto`
- Builder зарегистрирован в DI
- для нового компонента подключен `ExceptionResolver`, либо отдельно зафиксировано, почему он не нужен
- широкие `catch (\Throwable)` не глотают ошибку через `null`
- шаблон лежит в `local/templates/.../components/rebit/...`
- компонент реально ставится модулем
- на странице используется `rebit:<component-code>`

Пример быстрых проверок:

```bash
rg --files api/public/local/modules/rebit.example/install/components
rg --files api/public/local/modules/rebit.example/lib/Presentation/Component/Example
find local/templates -path "*/components/rebit/example.component/*/template.php"
```
