# HOW TO: сделать модуль

## 1. Создайте каркас

```text
local/modules/
`-- rebit.<name>/
    |-- di/
    |   |-- Layers/
    |   `-- <Domain>.php
    |-- install/
    |   |-- components/
    |   `-- index.php
    |-- lib/
    |   |-- Application/
    |   |-- Domain/
    |   |-- Infrastructure/
    |   |-- Presentation/
    |   `-- Shared/
    |-- include.php
    |-- routes.php
    `-- .settings.php
```

Минимум для нового модуля:

- `install/index.php`
- `include.php`
- `di/`
- `lib/`

Пример именования:

```text
local/modules/
`-- rebit.example/
    |-- di/
    |   `-- Product.php
    `-- lib/
        |-- Application/Product/UseCase/GetProductUseCase.php
        |-- Domain/Product/Repository/ProductRepository.php
        |-- Infrastructure/Product/Provider/Elastic/ElasticProductGateway.php
        `-- Presentation/Controller/Product/ProductController.php
```

Если модуль с API и компонентами, ориентир такой:

```text
local/modules/
`-- rebit.<name>/
    |-- di/
    |   |-- Facet.php
    |   `-- Layers/
    |       |-- Infrastructure.php
    |       |-- Presentation.php
    |       `-- Shared.php
    |-- install/
    |   |-- components/
    |   |   `-- <component-code>/
    |   |       `-- class.php
    |   `-- index.php
    |-- lib/
    |   |-- Application/
    |   |-- Domain/
    |   |-- Infrastructure/
    |   |-- Presentation/
    |   `-- Shared/
    |-- include.php
    |-- routes.php
    `-- .settings.php
```

## 2. Соберите `install/index.php`

Обязательно:

- `declare(strict_types=1);`
- класс модуля `extends CModule`
- `RegisterModule()` в `DoInstall()`
- `UnRegisterModule()` в `DoUninstall()`

Если модуль ставит компоненты:

- подключите `ModuleComponentInstallerTrait`
- вызовите `initModuleComponentInstaller()` в `__construct()`
- вызовите `installComponents()` / `uninstallComponents()`

Если модуль дает HTTP API:

- подключите `ModuleRoutingTrait`
- вызовите `initModuleRouting()` в `__construct()`
- вызовите `installModuleRouting()` / `uninstallModuleRouting()`

Если в модуле есть и компоненты, и API, используйте оба трейта.

Пример `install/index.php`:

```php
<?php

declare(strict_types=1);

use Bitrix\Main\InvalidOperationException;
use Bitrix\Main\SystemException;
use Rebit\Share\Infrastructure\Bitrix\Module\ModuleComponentInstallerTrait;
use Rebit\Share\Infrastructure\Bitrix\Module\ModuleRoutingTrait;

class Rebit_Example extends CModule
{
    use ModuleComponentInstallerTrait;
    use ModuleRoutingTrait;

    public $MODULE_ID = 'rebit.example';
    public $MODULE_VERSION = '1.0.0';
    public $MODULE_VERSION_DATE = '2026-03-14 00:00:00';
    public $MODULE_NAME = 'rebit.example';
    public $MODULE_DESCRIPTION = 'Пример нового модуля';

    /**
     * @throws SystemException
     */
    public function __construct()
    {
        $this->initModuleComponentInstaller();
        $this->initModuleRouting();
    }

    /**
     * @throws InvalidOperationException
     * @throws SystemException
     */
    public function DoInstall(): bool
    {
        RegisterModule($this->MODULE_ID);
        $this->installComponents();
        $this->installModuleRouting();

        return true;
    }

    /**
     * @throws InvalidOperationException
     * @throws SystemException
     */
    public function DoUninstall(): bool
    {
        $this->uninstallModuleRouting();
        $this->uninstallComponents();
        UnRegisterModule($this->MODULE_ID);

        return true;
    }
}
```

## 3. Сделайте `include.php`

Только bootstrap:

- проверьте зависимости модуля, например `rebit.share`
- зарегистрируйте `EventManager` handlers
- не кладите сюда бизнес-логику и UseCase orchestration

Пример `include.php`:

```php
<?php

declare(strict_types=1);

use Bitrix\Main\EventManager;
use Rebit\Example\Infrastructure\Product\Event\ProductChangedEventHandler;
use Rebit\Share\Infrastructure\Bitrix\Module\ModuleHelper;

ModuleHelper::validateModuleInstalled('rebit.share');

$eventManager = EventManager::getInstance();
$eventManager->addEventHandler(
    'iblock',
    'OnAfterIBlockElementUpdate',
    [ProductChangedEventHandler::class, 'handle'],
);
```

## 4. Соберите DI

Правило:

- все регистрации лежат в `di/`
- `.settings.php` только собирает итоговый массив `services`

Рекомендуемая раскладка:

- `di/Layers/Presentation.php`
- `di/Layers/Infrastructure.php`
- `di/Layers/Shared.php`
- `di/<Domain>.php`

Важно:

- `ServiceLocator` допустим только в DI-конфигах, bootstrap и entrypoint
- если интерфейсная запись требует factory, scalar-аргументы или ручную сборку, используйте `constructor`, а не `className + constructorParams`

Пример `.settings.php`:

```php
<?php

declare(strict_types=1);

return [
    'services' => [
        'value' => array_merge(
            require __DIR__ . '/di/Product.php',
            require __DIR__ . '/di/Layers/Presentation.php',
            require __DIR__ . '/di/Layers/Infrastructure.php',
            require __DIR__ . '/di/Layers/Shared.php',
        ),
    ],
];
```

Пример `di/Product.php`:

```php
<?php

declare(strict_types=1);

use Bitrix\Main\DI\ServiceLocator;
use Rebit\Example\Application\Product\Port\Outgoing\ProductGatewayInterface;
use Rebit\Example\Application\Product\UseCase\GetProductUseCase;
use Rebit\Example\Infrastructure\Product\Provider\Elastic\ElasticProductGateway;
use Rebit\Share\Infrastructure\Elastic\Factory\ElasticClientFactory;

return [
    GetProductUseCase::class => [
        'className' => GetProductUseCase::class,
        'constructorParams' => static function(): array {
            return [
                ServiceLocator::getInstance()->get(ProductGatewayInterface::class),
            ];
        },
    ],
    ProductGatewayInterface::class => [
        'constructor' => static function(): ProductGatewayInterface {
            return new ElasticProductGateway(
                ServiceLocator::getInstance()->get(ElasticClientFactory::class)->create(),
            );
        },
    ],
];
```

## 5. Разложите код по слоям

- `Domain` -> сущности, value object, доменные сервисы, ORM-репозитории домена
- `Application` -> UseCase, AppService, порты, `*InputDto`, `*OutputDto`
- `Infrastructure` -> Elastic, HTTP, Bitrix-специфика, legacy adapters
- `Presentation` -> компоненты, ViewModel, controller, command
- `Shared` -> общее только для модуля

Пример раскладки:

```text
lib/
|-- Application/
|   `-- Product/
|       `-- UseCase/
|           `-- GetProductUseCase.php
|-- Domain/
|   `-- Product/
|       `-- Repository/
|           `-- ProductRepository.php
|-- Infrastructure/
|   `-- Product/
|       `-- Provider/
|           `-- Elastic/
|               `-- ElasticProductGateway.php
|-- Presentation/
|   `-- Controller/
|       `-- Product/
|           `-- ProductController.php
`-- Shared/
    `-- Enum/
        `-- ProductModeEnum.php
```

## 6. Проверьте перед сдачей

- модуль ставится и удаляется без ошибок
- компоненты копируются при установке, если они есть
- маршруты регистрируются, если есть API
- `.settings.php` подключает все нужные DI-файлы
- новый код не тянет `ServiceLocator` в бизнес-слои

Пример быстрых проверок:

```bash
rg --files api/public/local/modules/rebit.example
rg -n "installModuleRouting|installComponents" api/public/local/modules/rebit.example/install/index.php
rg -n "ProductGatewayInterface::class" api/public/local/modules/rebit.example/di
cd api/public/local && ./vendor/bin/php-cs-fixer fix --config=php-cs-fixer.php
```
