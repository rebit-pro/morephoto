# HOW TO: определить слой

## Задайте 4 вопроса

1. Код нужен только для UI, шаблона, JSON-ответа или CLI-вывода?
`Presentation`

Пример:

```php
<?php

declare(strict_types=1);

namespace Rebit\Example\Presentation\Component\Product\ViewModel;

final readonly class ProductListViewModel
{
    public function __construct(
        /** @var list<string> */
        public array $titles,
    ) {}
}
```

2. Код знает про Bitrix (кроме ORM), HTTP, Elastic, внешний API, legacy или файловую систему?
`Infrastructure`

Пример:

```php
<?php

declare(strict_types=1);

namespace Rebit\Example\Infrastructure\Product\Provider\Elastic;

final readonly class ElasticProductGateway
{
    public function __construct(
        private \Elastic\Elasticsearch\Client $client,
    ) {}
}
```

3. Код описывает предметное правило, состояние сущности или инвариант?
`Domain`

Пример:

```php
<?php

declare(strict_types=1);

namespace Rebit\Example\Domain\Product\Service;

final readonly class ProductPriorityCalculator
{
    public function calculate(int $sales, bool $inStock): int
    {
        return $inStock ? $sales + 100 : $sales;
    }
}
```

4. Код склеивает шаги сценария и вызывает порты?
`Application`

Пример:

```php
<?php

declare(strict_types=1);

namespace Rebit\Example\Application\Product\UseCase;

use Rebit\Example\Application\Product\Port\Outgoing\ProductGatewayInterface;
use Rebit\Example\Domain\Product\Service\ProductPriorityCalculator;

final readonly class GetProductListUseCase
{
    public function __construct(
        private ProductGatewayInterface $productGateway,
        private ProductPriorityCalculator $priorityCalculator,
    ) {}
}
```

Если не подошло ничего из этого, обратитесь к архитектору.

## Короткая шпаргалка

- `Domain` -> Entity, Collection, ValueObject, доменный сервис, ORM-репозиторий домена
- `Application` -> UseCase, AppService, порт, `*InputDto`, `*OutputDto`, `*CacheEnum`
- `Infrastructure` -> адаптер, gateway, HTTP client, Elastic provider, legacy adapter
- `Presentation` -> component Builder, ViewModel, controller, command
- `Shared` -> enum, helper, exception, value object без привязки к одному сценарию

Пример раскладки:

```text
lib/
|-- Domain/Product/Service/ProductPriorityCalculator.php
|-- Application/Product/UseCase/GetProductListUseCase.php
|-- Infrastructure/Product/Provider/Elastic/ElasticProductGateway.php
|-- Presentation/Component/Product/ProductBuilder.php
`-- Shared/Enum/ProductModeEnum.php
```

## Где чаще ошибаются

- SQL / Elastic в `UseCase` -> это `Infrastructure`
- бизнес-правило в Builder или controller -> это `Domain` или `Application`
- форматирование ответа в `UseCase` -> это `Presentation`
- `ServiceLocator` в бизнес-коде -> нельзя

Неправильно:

```php
<?php

declare(strict_types=1);

namespace Rebit\Example\Application\Product\UseCase;

use Bitrix\Main\DI\ServiceLocator;

final class BadUseCase
{
    public function execute(): array
    {
        $client = ServiceLocator::getInstance()->get('elastic');

        return $client->search([]);
    }
}
```

Правильно:

```php
<?php

declare(strict_types=1);

namespace Rebit\Example\Application\Product\UseCase;

use Rebit\Example\Application\Product\Port\Outgoing\ProductGatewayInterface;

final readonly class GoodUseCase
{
    public function __construct(
        private ProductGatewayInterface $productGateway,
    ) {}
}
```

## Если сомневаетесь

- вопрос "какое правило предметной области?" -> `Domain`
- вопрос "в каком порядке выполнить шаги?" -> `Application`
- вопрос "как это сделать через конкретную технологию?" -> `Infrastructure`
- вопрос "как это показать наружу?" -> `Presentation`
