Отлично! Вот детализированный сценарий с акцентом на пользовательских сценариях:

ПОЛЬЗОВАТЕЛЬСКИЕ СЦЕНАРИИ P2P-ПРИЛОЖЕНИЯ
АКТОРЫ:
Гость - неавторизованный пользователь

Пользователь - авторизованный клиент с подключенным аккаунтом Bybit

Система - фоновые процессы

СЦЕНАРИЙ 1: ПЕРВИЧНАЯ АВТОРИЗАЦИЯ И НАСТРОЙКА
Предусловие: Пользователь зашел на сайт впервые.

Основной поток:

Гость нажимает "Войти"

Система перенаправляет на страницу входа Bitrix

После успешной авторизации Bitrix система проверяет наличие подключенного аккаунта Bybit

Если аккаунт не подключен → система показывает экран подключения API Bybit

Пользователь вводит:

API Key

Secret Key

Выбирает режим (тестовый/боевой)

Система:

Шифрует и сохраняет ключи

Выполняет тестовый запрос к API Bybit для проверки

При успехе → сохраняет подключение

При ошибке → показывает детали и просит проверить ключи

Альтернативный поток 4a:

Пользователь пропускает подключение → ограниченный функционал (только просмотр стаканов)

СЦЕНАРИЙ 2: ПРОСМОТР СТАКАНОВ P2P
Предусловие: Пользователь авторизован, находится на главной странице.

Основной поток:

Система автоматически загружает дефолтную валютную пару (USDT/RUB)

Пользователь видит:

Два стакана: Покупка (Buy) слева, Продажа (Sell) справа

В каждом стакане таблица с колонками:

Пользователь (имя/никнейм)

Цена (в рублях за USDT)

Доступно (количество USDT)

Лимиты (мин/макс сумма в рублях)

Методы оплаты (иконки)

Данные обновляются каждые 10 секунд

Дополнительные возможности:

Смена валютной пары:

Пользователь выбирает из списка: USDT/RUB, BTC/USDT, ETH/USDT и т.д.

Система перезагружает стаканы для выбранной пары

Фильтрация:

По методам оплаты (Тинькофф, Сбер, QIWI и др.)

По диапазону цен

По сумме (мин/макс)

Сортировка:

По цене (возрастание/убывание)

По доступному объему

По рейтингу контрагента

СЦЕНАРИЙ 3: СОЗДАНИЕ ЗАЯВКИ НА ПОКУПКУ
Предусловие: Пользователь просматривает стакан продаж.

Основной поток:

Пользователь кликает на конкретное предложение в стакане продаж

Открывается модальное окно с деталями сделки:

Контрагент: имя, рейтинг, % завершенных сделок

Цена: фиксированная из стакана

Лимиты: мин/макс сумма сделки

Доступно: максимальный объем

Срок оплаты: 15 минут (стандартно)

Пользователь вводит:

Сумму покупки (в USDT или RUB, с конвертацией)

Выбирает свой метод оплаты

Вводит дополнительные комментарии (опционально)

Система показывает:

Итоговую сумму к получению/отправке

Комиссию Bybit

Итоговую сумму с комиссией

Пользователь нажимает "Подтвердить"

Система:

Блокирует необходимую сумму на балансе пользователя

Отправляет запрос на создание ордера в Bybit API

При успехе → создает локальную запись о сделке

Переводит сделку в статус "Ожидание оплаты"

Показывает детали сделки с таймером 15 минут

Альтернативный поток 5a:

Недостаточно средств → система предлагает пополнить баланс

Ордер уже занят → система обновляет стакан и предлагает выбрать другой

СЦЕНАРИЙ 4: ОЖИДАНИЕ И ПОДТВЕРЖДЕНИЕ ОПЛАТЫ
Предусловие: Создана сделка в статусе "Ожидание оплаты"

Основной поток:

Система показывает страницу сделки с:

Данными контрагента и реквизитами для оплаты

Таймером обратного отсчета

Кнопкой "Я оплатил"

Чат для общения с контрагентов (опционально)

Пользователь совершает перевод по реквизитам

Пользователь нажимает "Я оплатил"

Система:

Уведомляет контрагента о поступлении оплаты

Переводит сделку в статус "Ожидание подтверждения продавцом"

Контрагент подтверждает получение оплаты

Система:

Разблокирует и переводит активы покупателю

Завершает сделку

Обновляет балансы обоих участников

Добавляет запись в историю

Альтернативный поток 3a:

Таймер истек → система автоматически отменяет сделку

Контрагент не подтвердил оплату → система запускает арбитраж

Пользователь нажимает "Отменить" → отмена с возвратом средств

СЦЕНАРИЙ 5: ПРОСМОТР ЛИЧНОГО КАБИНЕТА
Основной поток:

Пользователь переходит в "Мой кабинет"

Вкладка "Балансы":

Таблица с валютами: доступно, заблокировано, всего

Кнопка "Пополнить" / "Вывести" для каждой валюты

График изменения баланса за период

Вкладка "Активные сделки":

Текущие сделки с фильтрами: все, покупка, продажа

Возможность отмены для активных сделок

Детальный просмотр каждой сделки

Вкладка "История сделок":

Таблица завершенных сделок с пагинацией

Фильтры: дата, тип, валюта, статус

Экспорт в CSV

Вкладка "Статистика":

Оборот за периоды (день, неделя, месяц, год)

Прибыль/убыток (в рублях и в процентах)

Количество сделок

Графики: оборот по дням, распределение по валютам

Сравнение с предыдущим периодом

СЦЕНАРИЙ 6: СОЗДАНИЕ СОБСТВЕННОГО ОРДЕРА (МАРКЕТ-МЕЙКЕР)
Предусловие: Пользователь хочет выставить свое предложение

Основной поток:

Пользователь нажимает "Создать объявление"

Выбирает тип: Продать / Купить

Выбирает валютную пару

Заполняет параметры:

Цена (фиксированная или плавающая)

Доступное количество

Лимиты сделки (мин/макс сумма)

Выбор платежных методов (один или несколько)

Условия сделки (комментарий)

Система показывает предварительный расчет и комиссию

Пользователь подтверждает

Система:

Блокирует указанный объем на балансе

Отправляет ордер в Bybit API

Добавляет предложение в стакан

Уведомляет при появлении покупателей/продавцов

СЦЕНАРИЙ 7: ФОНОВЫЕ ПРОЦЕССЫ СИНХРОНИЗАЦИИ
Процесс 7.1: Синхронизация стаканов

Каждые 10 секунд: запрос к Bybit API за обновлениями

Обновление локальной БД

Отправка push-уведомлений подключенным клиентам об изменениях

Очистка устаревших ордеров (старше 5 минут)

Процесс 7.2: Синхронизация балансов

При входе пользователя

После каждой завершенной сделки

Раз в 5 минут для активных пользователей

Обновление локального кеша балансов

Процесс 7.3: Синхронизация истории сделок

При первом подключении аккаунта: загрузка всей истории

Затем каждые 10 минут: дозагрузка новых сделок

Синхронизация статусов активных сделок

Процесс 7.4: Проверка истекающих сделок

Каждую минуту проверка сделок с истекающим таймером

Автоматическая отмена при истечении времени

Уведомление пользователей за 5 минут до истечения

8.3: Сессии и устройства
